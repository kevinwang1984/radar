01 Qwen3.8-27B-pi-adapted：关掉思考，用 LoRA 把 SWE-bench 拉到 64.7% 让本地编程 Agent 省 4 倍 token。 中文 1 小时 cn:juejin ›
是什么Hugging Face 11-18 开源 `harness-hub/Qwen3.8-27B-pi-adapted`，Apache-2.0 的 Rank-32 LoRA，不换 Qwen3.8-27B 基座；用 AsyncGRPO（TRL）在 `pi` 编程代理的真实命令行环境里做强化学习，训练时关掉 thinking。SWE-bench Pro hard-51 的 pass@1 从 39.2% 提到 64.7%，Terminal-Bench 2.1 从 39.5% 提到 55.8%，每个任务生成 token 约为基座最高推理档的 1/4.5，回合数不到一半；vLLM 挂上 LoRA 后把 pi 指到 `localhost:8000` 即可，另有 GGUF 版可跑 llama.cpp。 为什么值得你花时间你在本地跑编程 agent 时，最大的两笔账是显存和等待；这条把「多步推理」的成本提前压进离线 RL 权重，关掉 thinking 仍追平最高推理档，等于同样的卡跑更多任务。今天可以用 vLLM 挂 adapter、按模型卡的命令起 pi，跑一条你最近返工最多的真实 issue，记录 token、回合数和是否真修对；没有大显存就先下 GGUF 在 llama.cpp 试 Q8_0。边界：强绑 pi 的提示词与工具约定，换到 OpenCode 或普通对话不会自动迁移；thinking 被固化关掉，强行打开只多约 4 倍 token、没有准确率收益；hard-51 只有 51 题、Terminal-Bench 86 题，95% 置信区间约 ±14.2 / ±9.1 点；GGUF 版尚未完整复测，低比特量化会漂。 上手成本1 小时（vLLM 挂 LoRA + pi 跑一条真实任务） 入口https://huggingface.co/harness-hub/Qwen3.8-27B-pi-adapted （文章 https://juejin.cn/post/7709381318992478262） 读详情（翻译 + 要点）→
02 media-use：给视频 Agent 一个带账本的素材入口 给视频 Agent 找素材、记账、离线复用。 技能 15 分钟 skills:trending ›
是什么HyperFrames 的 9 个 skill 之一，装法是 `npx skills add heygen-com/hyperframes --skill media-use`，或 `npx hyperframes skills update` 装核心集。核心命令 `npx hyperframes media-use resolve --type <type> --intent "<what you need>" --project <dir>` 只打印一行 `resolved <id> → <path>`；素材落进项目 `assets/` 并写一条 ledger，之后渲染不再联网取。它覆盖音乐、音效、图片、图标、logo、配音、数字人、生成视频、转录、抠图、调色，`--candidates` 先列可复用资产，`--from` 支持 ingest；skills.sh 趋势榜第 10（15.5K installs）。 为什么值得你花时间视频 / 画布流水线最烦的是素材散在临时目录、每次渲染重新下载、出问题复现不了；这个 skill 把「找或做素材」收敛成一个带账本的动作，agent 只读一行 resolved，人和 CI 都能查到用了哪个文件。今天可以在一个测试项目里装 skill，resolve 一张图加一段音乐，再重跑渲染确认没有新的 fetch，最后看 ledger 是否记录了这次解析。边界：它是 HyperFrames 生态的一部分，脱离 `assets/` + ledger 约定价值有限；skills.sh 上 Snyk 审计为 Fail、Socket 与 Agent Trust Hub 为 Warn，装进生产前先读脚本；`resolve` 会发 CLI 的 telemetry，可用 opt-out 关掉。 上手成本15 分钟（Node 22+，装 skill + resolve 一个素材） 入口https://www.skills.sh/heygen-com/hyperframes/media-use 读详情（翻译 + 要点）→

06 MoE 专家流式加载：180B 参数跑进 32GB 内存 把 180B 专家模型塞进 32GB 内存。 跟人 1 小时 people:hf-blog ›
是什么Hugging Face 博客 11-18 的实验：在 32GB M5 Mac 上用 Transformers 跑 Qwen3.8-Flash-Next（48 层 × 512 专家，FP8 121GB），专家量化到 3 bit（磁盘 49GB）、设备缓存 12GiB，dense 层 8bit（约 5.4GB），n-gram 表留磁盘按行读；用 slot pool 让 `grouped_mm` 直接吃缓存，`experts_offload={"cache_bytes": 12<<30}` + `device_map={"": "mps", "experts.*": "disk"}`，并对下两层路由做预取。最终 decode 13.9 tok/s（Strata 14.8）、4K prefill 228 tok/s（Strata 220），加载后约 18GiB、6K prompt 峰值 25.4GiB；代码在 Transformers PR #50717 和 `tarekziade/moe-expert-streaming`。 为什么值得你花时间如果你想在单机 / 消费级硬件上跑更大的 MoE，或者给本地 agent 省 API 费，这篇把「只流式读路由到的专家 + 有界缓存 + 预取」讲透了，还给了能跑的 PR 和 Space；它证明 121GB 专家可以在 32GB 内存里跑，代价是约 14 tok/s。今天可以在一台 32GB 机器上按 PR 装 Transformers，先用 OLMoE-1B-7B 验证 slot pool，再换 Qwen3.8-Flash-Next 看峰值内存。边界：14 tok/s 对编程 agent 仍然太慢；转换约 5 小时；6K prompt 时要关浏览器；API 还在和 maintainers 讨论；只在 M5 / Metal 上验证，换硬件要重测。 上手成本1 小时（装 PR + 跑 OLMoE） 入口https://huggingface.co/blog/moe-expert-streaming （PR https://github.com/huggingface/transformers/pull/50717） 读详情（翻译 + 要点）→
