是什么Earendil 与 Pi 社区 2026-10-01 发布 **Pi 1.0**（极简 coding agent 转正），同时放出实验性的 **Pi Durable**——一个 TypeScript 的 **harness 框架**（不替代 Pi coding agent，而是用来做任何 agentic 应用）。它把 harness 定义成「**存储 + 并行跑多个会话所需的机械**」，并立了一条总规则：**harness 跑的每一件事都是 task**。四条主干：**① 崩溃存活**——每一步先写 checkpoint 再往下走，进程死了新进程打开同一存储、找到未完成的 task 从最后检查点续跑；被切断的模型请求重发、半截回答标成 aborted 留在 transcript；工具调用**只有声明 `replay: "safe"` 才重跑**，否则告知模型「被打断了」；`requestId` 保证提交换取 **exactly-once**；子 Agent 是普通会话，同样能续跑。**② 跑在哪都行**——存储后端有 memory / SQLite / JSONL（附一致性套件与基准），**SQLite 与 JSONL 不用任何 Node API**，加个小适配器就能跑在 Bun 或 Cloudflare Durable Object 上；执行环境同理可换，「harness 在 A 机、工具在 B 机」成立。**③ 可塑**——扩展是「系统提示段 + 工具 + hook + task」的具名包，**会话只存名字、不存代码**，所以运行中换掉扩展文件，下一次调用就用新代码；提示段每次请求重建、变更记进 transcript 对应位置（重启或 fork 看到的与模型当时所见一致），对支持中途改提示的模型**只发增量、prompt cache 不失效**。**④ 多人与多会话**——一个 harness 跑任意多会话，会话可在任意位置 `fork` 且不复制父历史；应用状态（待办、计划、工单、沙箱）存成与 transcript **同一次原子提交**写入的 documents；任意多客户端可 attach，晚到者从当前视图开始、之后只收变更，任何客户端都能 steer（`whenBusy: "steer"`）。压缩也做成后台 task（`reserveTokens` 16384 / `backgroundTokens` 32768），**只有下一次请求真的放不下时才等摘要**，老消息永不删除、`reset()` 之后仍可用 `search_history` 搜到。不含测试约 **15,000 行**（≈150K GPT token），其中存储后端占 3,000 行。**要扣掉的分**：官方自标 experimental、API 可能变；「15,000 行 / 150K token」是自报数字，未第三方核验。 为什么值得你花时间你每天在做的事就是「让 Agent 跑长任务、且死了能接着跑」——radar 的 `run-daily.cmd`、`/implement` 的收尾、DSH 的 subagent 都是这个形状。这条最值钱的不是代码，是**四条可以直接抄的接口约定**：① **「每件事都是 task，task 先写检查点」**——把「能续跑」从个别工具的属性升级成框架的统一保证；② **工具必须自己声明可否重跑**（`replay: "safe"`）——这一条今天就该给你现有工具补上，因为它决定了崩溃后是「安全重试」还是「必须问人」；③ **会话只存名字不存代码**——热换扩展、重启即生效，不必迁移会话；④ **应用状态与 transcript 同一次原子提交**——「状态永远不会和产生它的对话不一致」这条不变量，正是你 09-29 记过的「状态外置」的更严格版本。还有一处细节值得单独记：**压缩在后台跑、不阻塞会话**，这比「上下文满了就停下来总结」体验好得多。想在 DSH 上验证，最小路径是照它的 `triage` 子 Agent 例子（约 20 行）写一个：子会话由工具调用 owned，abort 时自底向上级联清理。 上手成本半天（`npm install @earendil-works/pi-durable @earendil-works/pi-ai @earendil-works/chord`，跑通「杀掉进程 → 重启 → 从检查点续跑」的官方示例） 入口https://earendil.com/posts/pi-durable/ 读详情（翻译 + 要点）→
