01 DeepSeek 上线 Search / Fetch API：把网页查与读做成两个官方端点 把网页搜索与正文抓取做成两个官方 API。 其他 15 分钟 docs:deepseek-api ›
是什么DeepSeek 文档新增 `Search & Fetch` 一节：`POST /v1/tools/search` 找网页，`POST /v1/tools/fetch` 取单页并**直接返回 `title` + Markdown 正文**（`/api/fetch` 是今天候选里唯一的新增文档页）。两者都是裸 JSON、Bearer 鉴权、和模型 API 同一个 key；Search 支持 `site:` / `-site:` / `"精确短语"` / `lang:zh,en` / `after:2025-01-01` 等算子，`count` 1–50，`need_content` 决定是否连正文一起给，结果里带 `rerank_score`（0–3，≥1.5 算高质量）、`summary`（约 600–800 字，明确写「给模型读」）与 `authority` 分档；计费按**成功请求**算，Search 与 Fetch 各 **$0.75 / 1000 次**，失败、空结果、超时不计费；QPS 账户级各 5（Fetch 另有按域名限速），错误码区分 402 余额、403 策略拒绝、404 提不到正文。官方还写明：**Claude Code 内置 Web Search / Codex `web_search` 走的 Search 请求，上线头两周不收 Search 费**。 为什么值得你花时间你给 Agent 接网页的活（雷达抓原文、素材调研、竞品页面）现在要么自己写抓取 + 正文提取，要么拼第三方搜索，还要各自维护 key、重试与配额；这条把「搜 + 读」收成同一家、同一 key、同一个 Markdown 出口，折算下来一次不到 1 分钱，还能按站点/语言/时间过滤，省掉自己维护解析层。注意 QPS 只有 5（账户级），批量化时要排队；文档页本身没有「取网页」之外的能力，别把它当爬虫集群用。 上手成本15 分钟 入口https://api-docs.deepseek.com/guides/search 读详情（翻译 + 要点）→

是什么一个 81.3k stars、Apache-2.0 的开源项目（作者 Paul Bakaus，明确承认从 Anthropic 的 frontend-design Skill 起步），把「设计判断力」拆成两条轨道：一条是**不依赖 LLM 的 59 条确定性规则**，CLI 与浏览器扩展直接跑、不要 API key，专抓 AI 生成设计的固定特征（紫蓝渐变、卡片套卡片、彩色底配灰字、弹跳缓动、标题上方必有的圆角方图标、过小触控目标、行长过长），因此**免费、可复现、能进 CI**；另一条是 `/impeccable <command> <target>` 的 **24 个命令**驱动 LLM 做深评（`init` 写产品背景到 `PRODUCT.md`、`document` 从代码生成 `DESIGN.md`、`craft` 先定型再构建、`critique` UX 评审、`audit` 无障碍/性能/响应式、`polish` 上线打磨，还有 `bolder`/`quieter`/`distill`/`harden` 等）。架构上核心是一份 Rust 引擎二进制（首次运行下载到 `~/.impeccable/bin/`），Claude Code、Cursor、Codex、Gemini CLI 等十余种工具各配一个轻量启动器；`npx impeccable install` 即可，`npx impeccable detect src/` 或 `detect https://example.com` 无需 Skill、无需 LLM。 为什么值得你花时间你的平台要交付画布 UI、素材页、生成任务面板，而 AI 写的前端最容易「一眼假」——59 条规则可以直接当 CI 门禁，把审美问题变成确定性检查（且不烧 token）；`audit` 覆盖无障碍/性能/响应式，正好对上交付质量那一段；对你自己的技能体系也有借鉴：**把能确定性判断的部分留给规则引擎、把需要语境的部分留给 LLM**，比全部塞给模型便宜也可控。 上手成本15 分钟 入口https://github.com/pbakaus/impeccable 读详情（翻译 + 要点）→
