01 AgentRun：给 Agent 加自学习、断点续跑和审批台 给 Agent 加自学习、断点续跑和审批台。 小而美 1 小时 hn:show ›

02 Docker Sandbox Kit：把 Agent 权限写成可签名的 OCI 镜像 把 Agent 权限写成可签名的 OCI 镜像。 中文 1 小时 cn:infoq ›
是什么Docker 把 Sandbox Kit 规范捐给 CNCF，v3 改为普通 OCI 镜像，manifest 只声明 `vnd.docker.sandbox.kit.descriptor`，所以能 `docker buildx build`、`docker pull`，也能被扫描、签名或在 `FROM` 里引用。一个 Kit 打包 agent、它用的工具、以及一份类型化的权限申请（hosts / credentials / volumes），能力写成 `com.docker.sandbox/network-policy@2`、`com.docker.sandbox/credential@1` 这样的版本化声明；deny 优先，官方 GitHub CLI 示例允许 api.github.com 但拒绝对 `/repos/**` 的 DELETE。凭据由代理托管，真实 token 只注入到指定域名的请求里，沙箱内只有 sentinel。Kit 只是「申请」，最终由运行时裁定；Docker Sandboxes（microVM）是第一个符合规范的运行时，可以用 `sbx run ./hello --kit ./gh` 试。 为什么值得你花时间你在 Gitea 上跑 wayfinder、还会给画布 agent 开浏览器和沙箱，现在这些权限散落在 shell 历史、控制台看板和记忆里；这条把「这个 agent 能访问哪些域名、能拿哪些凭证、能挂哪些卷」变成可 diff、可扫描、可签名、可用 digest 固定的构件，CI 里能拦住权限扩大。今天用 sbx 跑一个 hello kit + 一个 GitHub kit，看你们 agent 的权限能不能这样写下来。边界：v3 的描述符语法和每项能力语义都是新的，要重新学；权限执行完全取决于运行时，目前只有 Docker Sandboxes 实现，跨运行时未验证；CNCF 的治理归属和成熟度等级还没公布；它是权限申请格式，不是沙箱本身。 上手成本1 小时（装 Docker + 跑 sbx 示例） 入口https://www.infoq.cn/article/yV89L6iMCqSLDHeSoLxo 读详情（翻译 + 要点）→
