01 hyperframes-registry：用现成积木拼 HyperFrames 视频 给 HyperFrames 装现成视频积木。 技能 15 分钟 skills:trending ›
是什么HeyGen 的 HyperFrames 把视频写成 HTML + data 属性 + GSAP，这个技能管的是它的素材库：`npx hyperframes catalog --query "<英文描述>"` 先在本地目录里检索，`npx hyperframes add <name>` 把 block（自带尺寸和时间轴的子合成）或 component（可直接粘进主合成的 CSS/JS 特效）写进项目；block 要用 `data-composition-src` 挂载，再用 `data-start`、`data-duration`、`data-track-index` 控制起点、时长和轨道。装法是 `npx skills add https://github.com/heygen-com/hyperframes --skill hyperframes-registry`。 为什么值得你花时间你做一句话成片 / 自动分镜，最耗时的往往不是模型，而是片头、转场、字幕条这些重复镜头；这个库把常见 beat 做成可搜索的现成块，装完就是项目里的普通源码，能改能删，15 分钟能拼出一条可渲染的样片。边界：目录以英文索引，中文需求要先翻成英文；默认只做词面匹配，语义检索要一次性下载约 33MB 模型；每次 `add` 仍要联网。 上手成本15 分钟（Node/npx + 联网安装） 入口https://www.skills.sh/heygen-com/hyperframes/hyperframes-registry 读详情（翻译 + 要点）→
02 Omnara：可自托管的托管 Agent 平台 自托管跑 Agent 的平台，带沙箱和 API。 小而美 1 小时 hn:show ›
是什么Omnara 是 Apache-2.0 的托管 Agent 平台，定位是 Claude Managed Agents / OpenAI Agents API 的可自托管替代：一个 Agent 就是一段 YAML（instruction、model provider、tools、machine_sources），平台负责机器池与沙箱、密钥、权限、审批提问、事件流和 artifact，对外给 Web 界面、CLI、REST API 和 TypeScript SDK。文档示例里直接有一个 video generation agent。 为什么值得你花时间你现在的 Agent 大多绑在单台机器和一个宿主上，想做成平台能力就得自己补调度、沙箱、权限和审计；Omnara 把这层做成可自托管的产品，还能接任意模型和任意机器——内容平台的素材转码、批量分镜、发布前检查都能拆成独立 Agent 跑。边界：自托管要自己维护一套服务端依赖，项目较新，生产前先拿它的视频生成示例跑通。 上手成本1 小时（自托管；用云版 15 分钟） 入口https://github.com/omnara-ai/omnara 读详情（翻译 + 要点）→
03 Corgi：把多个编码 Agent 收进一个终端 把多个编码 Agent 收进一个终端窗口。 小而美 15 分钟 hn:show ›
是什么Corgi 是面向 Agent 的终端复用器（macOS / Linux / WSL2），一个窗口里管 Claude Code、Codex、Pi、OpenCode 的多个会话：每个 Agent 有 working / needs you / unread / clear 状态，F1 跳到需要你的那个；还能看每个工作区的 token 消耗、Agent 改过哪些文件、worktree 和资源占用，进程像 tmux 一样留在后台。`corgi --skill` 会把用法教给 Agent，⌘V 在 SSH 里也能直接贴图（要 Ghostty Nightly）。 为什么值得你花时间你在 wayfinder 里同时开几个 Agent 时，真正烦的是哪个跑完了、哪个在等我、刚才改了啥；Corgi 把这些状态收进一屏，15 分钟装完就能替换掉 tmux 加手工标签。边界：Windows 只能走 WSL2；原生远程连接还没做（作者说在路线图上）；安装是 `curl | bash`，生产机先读脚本。 上手成本15 分钟（macOS/Linux/WSL2） 入口https://corgi.computer/ 读详情（翻译 + 要点）→

05 React 19.3 browser()：让组件光明正大跳过 SSR 让组件声明式跳过服务端渲染的 API。 中文 15 分钟 cn:infoq ›
是什么React 19.3（9 月 9 日发布）加了 `react-dom/browser()`：客户端组件里 `use(browser())`，服务端渲染时组件暂停、把最近的 Suspense fallback 留在 HTML 里，浏览器水合后返回 undefined 再正常渲染；必须由客户端组件调用并放在 Suspense 边界内，否则 SSR 会失败。另有 `onBrowserBailout` 回调和 reason 参数，方便上报哪些组件跳过了 SSR。 为什么值得你花时间画布、节点编辑器这类界面大量读 localStorage、window、设备时区，过去的 mounted 标志和 `typeof window !== 'undefined'` 很容易造成水合不匹配；browser() 把「这段只在浏览器跑」变成框架级语义，还能按 loader 是否有 initialData 条件跳过。边界：官方文档仍标 Canary，生产要先确认发布通道；它替代的是框架逃生舱（next/dynamic 的 ssr:false、Astro 的 client:only），不是数据获取方案。 上手成本15 分钟（升级 react/react-dom 到 19.3） 入口https://www.infoq.cn/article/jNX6EAzqP34xRjqUMU1N 读详情（翻译 + 要点）→
