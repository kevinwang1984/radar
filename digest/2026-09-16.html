是什么一篇中文实操（掘金，2026-09-16）。核心判断是长任务掉链子多半不是模型变笨，而是上下文供给出了问题——同一个模型、同一份工具列表，两个 Agent 在第 10 轮看起来差不多，到第 50 轮就一个还记得改过哪些文件，另一个开始重复读文件、忘记约束。作者把它拆成五个可组合动作：Offload（太挤先搬到文件 / 数据库）、Reduce（压成摘要、占位符或更短表示）、Retrieve（按需检索回来）、Isolate（装不下就拆成多个独立上下文）、Cache（复用已有计算结果）。压缩再分三层：Microcompact 只清旧工具结果、保留消息结构（替换成 `[Old tool result content cleared]`），Snip 从历史头部直接删消息（永久丢失，需要状态系统标记不可删项），再往上才是摘要。另一个关键区分是「全量预填充」与「Just-in-time」——按成本递增用工具：先 Glob 拿路径、再 Grep 拿命中行、最后 Read 读最可疑的文件；RAG 与 Agentic Search 都属于 JIT，区别只在「要不要搜」由系统还是由 Agent 决定。 为什么值得你花时间你正在搭的 agent 要跑几十轮的长流程，这份清单给的正是「哪一层该丢什么、什么时候丢」的操作口径，连 microcompact 的替换文案和工具的成本阶梯都能直接搬进你的 harness；15 分钟读完就能给现有链路挑出一两处该 offload 的地方。 上手成本15 分钟 入口https://juejin.cn/post/7685644889096486963 读详情（翻译 + 要点）→
