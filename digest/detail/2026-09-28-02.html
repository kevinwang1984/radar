ppt-master：让 Agent 直接产出原生可编辑 PPTX

在编码 Agent 里把文档生成原生可编辑 PPTX 的工作流。
其他 15 分钟（读示例与定位文档；跑通第一份约 30 分钟） weekly:github-seed

摘要 · 译自原文

PPT Master 是一个 MIT 许可的开源项目（仓库 `hugohe3/ppt-master`，当前 56.6K 星），定位是「AI 从任何文档生成原生 PowerPoint」。它不是又一个「让模型吐 Markdown 再套模板」的方案，而是一套跑在 Agent 内部的工作流（作者称之为 skill）：把 PDF、DOCX、网页或直接粘贴的文本交给任意具备 Agent 能力的 AI 工具，它在本机完成内容分析、结构推理、视觉设计与 PPTX 导出，全程除模型通信外不离开你的机器。作者是财务背景（CPA · CPV · 咨询工程师）的 Hugo He，动机很直白——他经常审阅和修改演示文稿，希望 AI 生成的幻灯片**在 PowerPoint 里仍然可编辑**，而不是被压成一张图片。项目明确写了三条承诺：成本透明可预测（免费开源，唯一成本是自己的模型用量，没有额外的 PPT 订阅）、数据留在本地、没有平台锁定（Claude / GPT / Gemini / Kimi 都能驱动，任何支持读写文件与执行命令的 Agent IDE 都能跑）。

技术上的核心差异是**原生深度**，而且作者把它描述成「行进方向而不是固定清单」。输出的 `.pptx` 是 PowerPoint 自身的对象模型：原生形状与连接线（带可用的调整手柄）、按需生成的数据驱动图表与表格、完整的文字 / 图片 / 填充 / 效果模型——任何元素点开都还能当原生 PowerPoint 对象继续编辑；走模板 / 结构化路线时还能拿到真实的幻灯片母版与版式（`p:sldMaster` / `p:sldLayout` 继承）。默认流程会把图表和表格输出成可编辑形状，加 `--native-charts-and-tables` 则生成带「编辑数据」的 PowerPoint Chart / Table 对象并另存为 `_native_charts_tables.pptx`；公式编译成可编辑 OMML（PowerPoint 2010+）。仓库里那份 `docs/powerpoint-svg-mapping.md` 是「PowerPoint ↔ SVG」的逐特性差距记录，并声明 **SmartArt 是有意不做而不是遗漏**。除从零生成外还有两条路线：**Edit Native PPTX**（把已有 `.pptx` 填进新内容，保留设计、未改动页面按字节保留，支持选择 / 重排 / 加备注与旁白），以及给成品加原生转场、动画与旁白。

上手门槛被压得很低：唯一需要预装的是 Python 3.10+，其余 `pip install -r requirements.txt` 一行搞定（Windows 有单独的分步指南，包含 PATH 与执行策略）；文档格式方面 `.docx` / `.html` / `.epub` / `.ipynb` 由 Python 原生处理，只有 `.doc` / `.odt` / `.rtf` / `.tex` / `.rst` / `.org` / `.typ` 这类遗留格式才需要 pandoc。也可以走 skill 市集安装：`npx skills add hugohe3/ppt-master`，或 Claude Code 里 `/plugin marketplace add hugohe3/ppt-master` + `/plugin install ppt-master@ppt-master`（这两条只取技能文件，后处理脚本仍需在安装位置 pip 装依赖）。默认会先跟用户确认设计规格（模板、16:9、页数），说一句「快速生成、不用跟我确认」则跳过往返直接出稿——快速模式是一次过、不可续、也没有 `svg_final/` 预览，作者明确说它省掉的是交互与长期规划，不是呈现能力。配图两条路：用 Agent 宿主自带的生图工具或 `image_gen.py`（需配 `IMAGE_BACKEND` 与对应 `*_API_KEY`，`gpt-image-2` 是当前最佳默认），或 `image_search.py`（零配置走 Openverse / Wikimedia，配 `PEXELS_API_KEY` / `PIXABAY_API_KEY` 会明显提升现代图库、人物与生活场景的覆盖，许可 CC0 / 公有领域 / Pexels 与 Pixabay 免署名 / CC BY / CC BY-SA 自动处理并自动加署名）。作者还专门写了边界：「这是工具不是许愿池」——`harness + model = agent`，工具只拥有流程、模型决定上限，推荐 1M 上下文的 Kimi K3 或 Claude 配合生图模型，并且**一次过不等于成品**，剩下打磨的活本来就是留给你的（因为原生可编辑，所以才有可能继续打磨）。

要点

  • MIT 许可，仓库 `hugohe3/ppt-master`，56.6K 星；只需 Python 3.10+，唯一安装命令 `pip install -r requirements.txt`
  • 输出是原生 DrawingML：原生形状与连接线（带调整手柄）、数据驱动图表与表格、`p:sldMaster` / `p:sldLayout` 母版继承；`--native-charts-and-tables` 生成带「编辑数据」的 Chart / Table 对象；公式为可编辑 OMML
  • 三条路线：从文档新建、Edit Native PPTX（保留设计、未改动页面字节级保留、支持选择 / 重排 / 备注 / 旁白）、给成品加原生转场动画与旁白
  • 安装也可走技能市集：`npx skills add hugohe3/ppt-master` 或 Claude Code 的 `/plugin marketplace add` + `/plugin install ppt-master@ppt-master`
  • 配图：`image_gen.py`（`gpt-image-2` 为最佳默认）或 `image_search.py`（零配置 Openverse / Wikimedia，配 Pexels / Pixabay key 更佳，许可自动处理并加署名）
  • 作者立场：`harness + model = agent`，工具只拥有流程、模型决定上限；一次过不等于成品；SmartArt 是有意不做

为什么值得你花时间

你在做内容生成平台，「把长文档压成一份能交付的成品」是同一类问题，而这条给的是**可执行的验收口径**——不是「生成得像不像」，而是「拿到的东西还能不能在 PowerPoint 里继续改」。那张 PowerPoint ↔ SVG 映射表（逐个特性记录差距，并声明 SmartArt 是有意不做而非遗漏）可以直接当成审自己平台导出物的清单：原生形状 vs 一张贴图、母版继承 vs 扁平文本框、图表是数据对象 vs 图片。第二层是它把「技能 = 工作流、模型只决定上限」写得毫不含糊，和你 AGENTS.md 里「技能是纪律不是介绍」是同一套思路。15 分钟用它自带的在线示例就能判断值不值得装。
