用 Seed-2.1-pro 做的电商视觉工作台：可确认、可复用、可验收

把参考图拆成可确认配方，再批量出商品图。
中文 1 小时（读复盘；跑起来需自备方舟 Key） cn:juejin

摘要 · 译自原文

作者「一点一木」用 Seed-2.1-pro-0915 做了一个叫 **Visual Director** 的电商商品图工作台：本地优先、自带密钥、开源仓库在 `chnjames/visual-director`，另有在线体验站。它要解决的不是「再造一个生图页面」，而是**把一次成功的生成方法存下来，让人能检查、能修改、能发布、能复用到下一批商品**。产品形态上是节点式画布，参考图辅助模板默认露出五个节点：参考图分析、商品图、提示词编辑与优化、商品场景生成、结果展示。

能力侧有六个关键设计。**参考图分析与视觉配方**：上传 1–5 张参考图，模型把画面解析成 12 个结构化字段（用途、主体位置、拍摄角度、构图、背景、光线方向、光质、调色、材质表现、氛围等），每个字段带置信度与图像证据，且只描述画面本身，不猜测、不声称还原了原图 prompt。**商品身份锁定**：从同一商品 2–3 张多角度照片提取形状、部件、颜色、材质、Logo、纹理等候选特征，全部默认「待确认」，只有人工确认后才变成不可改变的硬约束。**结构化提示词确认**：提示词由已确认的配方与身份编译生成，只读可核对，自由文本不能反向覆盖已确认的结构。**四维验收**：商品身份 0.4、视觉配方 0.3、场景任务 0.2、技术质量 0.1，严重错误一票否决，证据不足一律标「需人工复核」。**定向修复**：只针对问题点修一次再重新生成，形态、Logo、材质、虚构文字等高风险问题必须停车等人。**版本与批量**：发布后的版本不可变，批量任务只接受已发布版本，多件商品共享同一套参考风格，每行素材 / 状态 / 结果 / 错误独立，某一件出问题不影响整批，只有密钥、额度、服务端这类系统级错误才让整批暂停；刷新页面时仍在跑的任务一律判为中断，需手动恢复。首版面向静物电商（陶瓷、花瓶、香薰、摆件），明确不承诺人像换装与复杂包装文字渲染。

工程与实测数据也给了：开发全程在豆包工作中完成，模型是 Seed-2.1-pro-0915（方舟 API 名 Seed-Evolving），出图用 doubao-seedream-5-0-pro-260628。阶段一用时 **33 分 22 秒、从零创建 43 个工程文件、分两次提交 Git**，技术栈 React + TypeScript + Vite + Zod + Vitest；投稿前 **44 个测试文件 / 333 个用例全部通过**。节点库共定义 35 个节点，其中 **只有 5 个接通执行适配器，30 个仍是「规划中」**（能拖进画布但不能运行或发布）。真实运行记录：9 月 22 日凌晨到上午共四次，一次成功三次超时（两次卡在参考图分析、一次卡在图片生成，阈值都是 180 秒）；成功那次参考图辅助全流程（两次模型调用）**203.8 秒**，两次直接生成分别是 **90.5 秒 / 89.2 秒**；后来把生成超时放宽到 300 秒并加 1K 预览才跑通。作者明确写了边界：**批量引擎代码写完但还没用真实商品完整跑过**，页面上的行为来自设计与单测，不代表已验证稳定。

要点

  • 用 **Seed-2.1-pro-0915**（VLM + Coding）+ **doubao-seedream-5-0-pro-260628**（出图）搭的开源工作台：repo `chnjames/visual-director`
  • 参考图拆成 **12 个结构化字段**，每字段带置信度与图像证据；商品身份默认「待确认」，人工确认后才成为硬约束
  • 四维验收权重：**商品身份 0.4 / 视觉配方 0.3 / 场景任务 0.2 / 技术质量 0.1**，严重错误一票否决
  • 工作流发布后版本不可变；批量每批 ≤5 件 × 2–3 张，单件失败不拖垮整批，刷新页面任务判中断
  • 真实数字：阶段一 33 分 22 秒建 43 个文件；44 个测试文件 / 333 用例通过；35 个节点仅 **5 个接通**；全流程 203.8 秒、直接生成 90.5 / 89.2 秒；**批量未用真实商品验证过**

为什么值得你花时间

这是本轮唯一一条「画布 + 商品图批量」的完整工程样本，取舍几乎逐条对着你的平台：哪些判断让模型给、哪些必须留人工闸门、工作流怎么冻结成版本、批量怎么隔离失败、刷新页面时任务一律判中断而不是假装还在跑。5 分钟先看它的四维验收与「只读提示词」两处设计——回答的正是你现在最容易被投诉的「改一处崩全图」和「同批商品风格不统一」。
