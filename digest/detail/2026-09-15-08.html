ZGCM-1：7 名博士生 3 个月从零训练 7B 大模型

7 名博士生带几百个 agent 训出的开源 7B 模型。
中文 1 小时（仓库 + 技术报告；复现训练另算） cn:qbitai

摘要 · 译自原文

北京中关村学院 7 名博士生用一个暑假从零训练出 7B 模型 ZGCM-1，并把权重、各阶段 checkpoint、训练代码、数据配方和训练日志全部开源。工程上最值得看的是长上下文方案：局部注意力与全局注意力结合，训练中把上下文从 16K 逐步扩到 64K、256K，256K 下相对全注意力方案吞吐约 3.94 倍、KV cache 占用降到约六分之一；训练侧结合 Muon 与 FP8，用延迟缩放与 TWEO 抑制极端激活值改善低精度稳定性，16K 预训练达到同等 loss 的效率比标准 BF16/AdamW 基线提高约 4.2 倍。一次「loss 还在降但能力退步」的事故把问题追到了数据分片与 shuffle——实际送进训练的数据比例发生了波动，此后他们不再只盯 loss，而是更密集地保存 checkpoint，并建了 ACE 原子能力评测体系：把能力拆成 18 类、183 项、2503 个探针，分布式评测下一轮诊断约 2–3 分钟。

组织方式上，7 个人给自己组了几百个 agent 的子团队，分工做数据、跑实验、做评测，还搭了论坛式的任务发布与汇报系统，用自研 ZGent 平台把会议讨论和研发决策积累成共享上下文、把验证过的脚本与 debug 经验沉淀成可复用 Skill。团队把研发拆成 11 类任务按 L1–L5 评自主性：实验监控与部署到了 L4（给定目标与约束后可独立规划执行并按反馈调整），模型架构与学习算法设计仍在 L2。经验结论里有反直觉的两条：SFT 阶段更严格的质量筛选让样本减少约 44.9%，整体评测反而提升；长思维链数据比例过高会损害指令遵循。

要点

  • 开源入口：代码与技术报告 github.com/zgcagi/ZGCM-1，权重 huggingface.co/zgcagi/ZGCM-1-7B，数据 huggingface.co/datasets/zgcagi/ZGCM-1-Data
  • 长上下文：16K → 64K → 256K，256K 下吞吐约 3.94×、KV cache 约 1/6
  • 训练效率：Muon + FP8 + 延迟缩放 / TWEO，16K 达到同等 loss 比 BF16/AdamW 基线快约 4.2×
  • 评测：ACE 体系 18 类 / 183 项 / 2503 探针，一轮诊断 2–3 分钟
  • 组织：几百个 agent 分数据/实验/评测子团队；11 类任务自主性评级中部署与监控到 L4、架构设计仍 L2
  • 反直觉结论：SFT 更严格的质量筛选砍掉约 44.9% 样本，整体评测反而提升

为什么值得你花时间

这是目前最完整的一份「AI4AI」公开施工记录——代码和数据都在，SFT 质量筛选砍掉约 44.9% 样本反而整体变好、长思维链比例过高伤指令遵循这类结论可以直接拿去用；它把「几百个 agent 跑长流程」的组织方式（共享上下文 + 把验证过的脚本沉淀成可复用 skill）也完整写出来了，对你在平台上做 agent 编排是现成参照。
