同一模型在不同供应商下行为不同

讲清 OpenRouter 把同一模型路由到不同供应商的坑。
跟人 15 分钟 people:simonwillison

摘要 · 译自原文

这是一条 Simon Willison 的链接博客（2026-09-11），转的是 Mohamed Moustafa 的《So you want to use OpenRouter?》。OpenRouter 的一大卖点是「自动处理故障转移、并为每次请求挑最划算的选项」，也就是你只调一个端点，由它路由到当前可用的最佳后端供应商。

问题在于不同供应商跑的是不同的推理软件，优化与配置各不相同，于是同一个 OpenRouter 端点上的同一个模型可能表现出不一样的行为：有的供应商为视觉模型提供的服务甚至不具备视觉能力，reasoning effort 选项的处理方式也有差异。解决办法是控制路由——用 `provider.only` 只允许指定供应商，再用 `/endpoints` 方法列出某个模型 ID 当前有哪些供应商可选。

要点

  • 同一模型 ID 经不同供应商，行为可能不同（推理栈与配置不同）
  • 已知坑：部分供应商的视觉模型没有视觉能力；reasoning effort 处理不一致
  • 收敛手段：`provider.only` 指定允许的供应商
  • 查询手段：`/endpoints` 返回某模型 ID 的可用供应商列表
  • 出自 Mohamed Moustafa 的实践文，Simon Willison 作链接推荐

为什么值得你花时间

你的平台大概率会用聚合网关摊薄成本，这条把「便宜但换了后端」这个隐性变量摆上台面；花 15 分钟加一个 provider 白名单和一次端点查询，能省掉「同样 prompt 昨天好好的今天变差」的排查。
