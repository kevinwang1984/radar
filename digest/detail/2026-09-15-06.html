Harness Engineering 入门：Agent = Model + Harness

把 agent 理解为模型加外围执行环境的方法论。
中文 15 分钟 cn:juejin

摘要 · 译自原文

一篇中文入门，围绕 LangChain 的 Vivek Trivedy 在 2026 年 3 月提出的公式展开：Agent = Model + Harness，如果你不是模型，你就是 Harness。文章用发动机与整车打比方——模型负责生成、推理、决策，Harness（系统提示词、工具、文件系统、沙箱、编排逻辑、Hook、可观测性）负责把模型生成的文本变成真实行动；Claude Code 本身就是一个 Harness，而你在里面写的 CLAUDE.md、Skills、Hooks、MCP 是建在它之上的你自己的 Harness。

文章把 Harness 拆成七层：Instructions（CLAUDE.md / AGENTS.md / Skill 定义 / 编码规范）、Knowledge（记忆存储、上下文压缩、检索、进度文件）、Tools（文件读写、Shell、搜索、MCP 集成）、Infrastructure（文件系统、沙箱、浏览器、执行环境）、Orchestration（子 agent 生成、模型路由、交接、上下文防火墙、权限门）、Hooks / Middleware（由 Harness 而非模型运行的确定性生命周期脚本）、Observability（日志、追踪、成本计量、事件总线），并给出排查顺序：agent 出问题，从第一层往下问「哪一层失败了」。与 Loop Engineering 的关系是一层之差——Loop 决定下一步干什么、什么时候停，Harness 决定这一次怎么可靠执行。最实用的坑：CLAUDE.md 是作为上下文加载、不是作为配置强制执行，模型通常遵守但永远不保证，上下文塞满时就会被忽略，所以合规、安全类硬规则必须落到 Hook 这种模型无法幻觉绕过的确定性脚本上。

要点

  • 公式：Agent = Model + Harness（LangChain 的 Vivek Trivedy，2026 年 3 月）
  • 七层：Instructions / Knowledge / Tools / Infrastructure / Orchestration / Hooks / Observability
  • 排查法：出问题从第一层往下问「哪一层失败了」
  • 与 Loop Engineering 的分工：Loop 决定干什么，Harness 决定怎么执行
  • 硬规则不能只写 CLAUDE.md，要用 Hook 强制（上下文满了规则会被忽略）

为什么值得你花时间

你天天在写 skill、hook 和 AGENTS.md，却缺一个「哪层薄了就补哪层」的统一框架；这篇 15 分钟读完就能当排查清单用，也能解释为什么同一个模型在别人手里稳、在你手里要逐句补救。
