多智能体分解的产出守恒律

用生产日志算出每加一层子代理只拿回一半。
中文 15 分钟 cn:juejin

摘要 · 译自原文

这篇掘金文章拆的是论文《Decomposition Buys Integrity, Not Yield》（作者 Rong He，arXiv:2609.17464，2026-09-15 提交，cs.MA / cs.AI / cs.DC，附完整实验代码）。它问的是：把任务拆成 agent 树之后，叶子节点发现的东西到底有多少能活着到达根节点。模型很简洁：agent 拿到 b 个条目时保留任意一条的概率是 r(b)=C·b^(−δ)，于是深度 k 的树对 N 个发现的产出是 **C^k·N^(1−δ)**。若 r(b)=1/b，任何树、任何规模的产出都恰好是 1 个发现（作者用 20,000 棵随机不规则树验证到 2.4×10⁻¹⁵）。

实测数字（来自 600 条生产 deep-research 轨迹）：δ=0.34，置信区间 [0.30, 0.38]，用三种failure mode互不相同的识别方法交叉验证；在「条目边界由工具给定」的 hop 上（b=1 出现 550 次），C=0.571 [0.527, 0.615] 是直接观测而非从幂律外推，样本 16,082 个 hop；另有 1,012 条标注轨迹显示每 16 份子 agent brief 就有 1 份跑偏，μ=0.939，于是每层实际代价 C·μ=0.536——两层只剩 0.287，三层 0.154。文章点出分层的两个正当理由都不在产出上：根节点上下文是唯一贯穿全程且无法廉价遗忘的状态，深度把它的暴露量从 N 降到 N^(1/k)；成本上生产环境的扁平 agent 账单按 N^1.39 增长（不是朴素追加预期的 N²），等花费下两层在 **N=403 个发现**处超过扁平，而任务规模跨 14 个数量级、最优层数只从 2 增到 7 层左右。

最有工程价值的一条反直觉结论：委托不是对「上下文快满」的应急反应——743,819 次生产工具调用的 hazard 模型（只用决策前信息）显示，上下文每翻一倍委托的 odds ratio 是 0.969，置信区间完全在 1 以下；委托其实是**开局动作**。文中还给了一个下午就能跑完的自测方法：测 C（找「工具返回编号列表 → agent 写一轮输出」的 hop）、测 δ（固定架构让 N 翻倍做回归）、测 μ（抽样标注 brief 与实际行为）。

要点

  • 产出模型 C^k·N^(1−δ)：深度每层只贡献 C≤1 的衰减，δ 是指数、无法靠架构摆脱
  • 600 条生产轨迹测得 δ=0.34 [0.30,0.38]；C=0.571 [0.527,0.615]，观测自 16,082 个 hop
  • 每 16 份子 agent brief 就有 1 份跑偏（μ=0.939），每层实际代价 C·μ=0.536，两层剩 0.287、三层 0.154
  • 等花费下两层在 N=403 个发现处超过扁平；任务规模跨 14 个数量级最优层数只增约 7 层
  • 委托是开局决策而非应急：743,819 次工具调用显示上下文翻倍让委托 odds ratio 降到 0.969
  • 论文代码见 arXiv:2609.17464 附录（code/、findings.md）

为什么值得你花时间

你正在搭的 agent 编排迟早要回答「要不要再拆一层」，这篇给的是可以直接写进设计文档的系数和决策树（N<50 别分层、50–400 看根节点、>400 分 2–3 层），还附了「先测自己的 δ 和 C」的测量方法；15 分钟读完，能立刻给现有链路加一条「子 agent 找到的发现有多少活到了最终输出」的监控。
