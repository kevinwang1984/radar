把 Claude Code 云端环境逆向成一份基础设施图纸

拆开 Claude Code 的云端沙箱，还原出快照启动与部署协议。
方法 15 分钟（读法；无需自己拆二进制） hn:stories

摘要 · 译自原文

作者（在做名为 ArcBox 的本地 / 云端沙箱项目）在一次 Claude Code 会话里，用 `strace`、`strings`、`objdump`、`go tool objdump` 这些标准工具把运行环境拆开，得到一份完整的架构报告。第一层是 Firecracker MicroVM：`dmesg` 里 ACPI 表的 OEM ID 是 `FIRECK`、creator ID 是 `FCAT`，与 AWS Lambda / Fargate 同源；规格为 4 vCPU（Xeon Cascade Lake 2.80GHz）、16GB RAM、252GB 磁盘、Linux 6.18.5，且按 Firecracker 的设计不开放嵌套虚拟化。进程树极简，PID 1 不是 systemd 而是自写的 `process_api`——同时充当 init 与 WebSocket API 网关（2024 端口管进程、2025 端口管容器生命周期，共 6 个端点），用 epoll 轮询 `/proc` 监督子进程。

会话不从零启动，而是从冻结快照恢复：dmesg 显示模板创建与本次恢复之间隔了 48.5 小时，恢复时宿主热插拔三块块设备（256GiB ext4 根盘、63.7MB 的 `/opt/claude-code` squashfs、12.1MB 的 `/opt/env-runner` squashfs），`process_api` 依次清页缓存、重挂 devtmpfs、`pivot_root`、挂 squashfs overlay、用 `clock_settime()` 修正墙钟（否则停在模板时间）、丢弃 CAP_SYS_RESOURCE 后开始接受连接。安全措施包括 `init_on_free=1`、CRNG 重新播种、`--block-local-connections`、JWT 鉴权与用完即清的 secret 处理。

第二个发现是一个 27MB **未 strip 的 Go 二进制** `environment-runner`（软链为 `environment-manager`），带完整调试符号与符号表，可从 `go version -m` 与符号名导出内部包结构（api / auth / claude / manager / mcp servers / orchestrator / podmonitor / sandbox / tunnel 等），其中包含 Git 凭据代理、K8s lease 管理、代码签名 MCP server、Supabase MCP server 与 BYOC（Bring Your Own Cloud）环境实现。第三层是在 `tunnel/actions/deploy/` 里发现的部署客户端：除了预期的 VercelClient，还有一个 AntspaceClient，对应一个全网零结果的内部 PaaS「Antspace」——三阶段协议（POST 建部署 → multipart 上传 `dist.tar.gz` → NDJSON 流式回报 packaging → uploading → building → deploying → deployed），文件上传是单包 tar.gz 而非 Vercel 的按文件 SHA 去重，构建在本地完成、只上传产物。第四层是 web 端应用构建器 **Baku**：Vite + React + TypeScript 模板在 `/opt/baku-templates/vite-template`，自动写入 Supabase 环境变量并挂 6 个 MCP 工具（建库、执行查询、应用迁移、列出迁移、生成类型、部署 Edge Function），pre-stop 钩子会在存在未提交 / 未推送改动、Vite 日志有错或 `tsc --noEmit` 报错时阻止会话结束；Baku 的默认部署目标就是 Antspace，Vercel 只是备选。

要点

  • Firecracker MicroVM（ACPI OEM ID `FIRECK`），4 vCPU / 16GB RAM / 252GB 磁盘；PID 1 为自写 `process_api`，2024 管进程、2025 管容器
  • 会话从冻结快照恢复：模板与恢复相隔 48.5 小时，热插拔 vda/vdb/vdc（256GiB ext4 + 63.7MB + 12.1MB squashfs）
  • 安全措施：`init_on_free=1`、CRNG 重播种、丢 CAP_SYS_RESOURCE、禁 localhost 连接、JWT 鉴权、secret 用后即清
  • 27MB 未 strip Go 二进制 `environment-runner`，可导出内部包结构与依赖（mcp-go、grpc、otel、datadog-go）
  • 未公开的 PaaS「Antspace」三阶段部署协议（建部署 → 上传 tar.gz → NDJSON 流式状态）；web 构建器 Baku 用 Vite+React，自动挂 6 个 Supabase MCP 工具

为什么值得你花时间

你在做引擎接入与画布沙箱，这份报告把「云端 coding 沙箱到底怎么摆」的每一层都摊开了——快照恢复流程、进程/容器协议、块设备热插拔、秘密清理，都是能抄的具体做法；另外它还说明白了一件事：Anthropic 自己在建 PaaS，idea 到上线不离开它的栈，这直接影响你对「平台边界画在哪」的判断。15 分钟读完，比你自己去拆一遍省一整天。
