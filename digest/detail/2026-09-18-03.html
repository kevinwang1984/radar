Claude Code Projects 重构与 3 万 Agent 内部实践

Coordinator 拆活、云上多分支并行改代码，共享记忆对齐上下文。
中文 15 分钟（读法；Projects 本体需 Pro / Max 且目前限 beta） cn:qbitai

摘要 · 译自原文

量子位 9 月 18 日对 Claude Code Projects 重构的报道。旧版 Projects 本质是「放提示词和参考文档的文件夹」，聊几轮上下文就乱；新版把它变成以对话为驱动的协作中心，架构核心是一个叫 Coordinator 的协调器。开发者只在主对话框给一个高阶目标——文中的例子是「把整个鉴权模块重构为 OAuth 2.0 并补齐自动化测试」——协调器把任务拆成子任务派给并行的工作线程，每个线程是跑在云端独立环境里的 Claude Code 实例，拥有隔离的代码副本并各自拉出独立 Git 分支，在后台同时推进代码与单测，完成后自动提交并生成 PR；协调器还会跟踪子任务之间的上下文依赖，提示先合并哪条分支、后测哪个模块。

新引入的共享记忆用来解决「多个 agent 各写各的」带来的信息损失：各分支沉淀的技术规范、架构决策与团队偏好实时同步回共享记忆，子任务不必重复粘贴配置。整个过程支持完全异步，合上电脑后仍可继续，也能通过移动端查看各线程进度并微调指令。官方同时承认多 Agent 不便宜，提醒注意 usage。

报道还整理了 Anthropic《衡量 AI 研发节奏》报告的内部数字：研发平台常态并发 3 万个 AI Agent、单月触发超 10 亿次模型决策；按 Epoch AI 制定的 AL0–AL5 自动化分级，AL4（AI 凭一个高阶指令端到端完成任务）研发任务占比 26%，而今年 2 月还不足 1%，半年约 26 倍；放宽到 AL3（深度人机协作）则超过 90% 的研发流程已经达到。监控方面称 8 月超过 10 亿次决策中拦截了约 0.002% 的高风险或异常行为。Projects 目前是 beta，先开放给部分 Claude Pro / Max 用户，一周内逐步放量。文中参考链接指向 claude.com/blog/projects-redesigned 与 anthropic.com/institute/measuring-pace-of-ai-development，这两个域名本次不可达，以上内容以量子位原文为准。

要点

  • Coordinator 拆解高阶目标 → 多个云端 Claude Code 实例并行，各自独立 Git 分支、完成后自动开 PR
  • 共享记忆实时同步技术规范、架构决策与团队偏好，子任务不再重复粘贴配置
  • 内部口径：常态并发 3 万 Agent、单月超 10 亿次决策；AL4 研发任务占比 26%（今年 2 月不足 1%），AL3 以上逾 90%
  • 8 月超 10 亿次决策中拦截约 0.002% 高风险 / 异常行为；官方提醒多 Agent 成本高
  • Projects 现为 beta，先给部分 Pro / Max 用户，一周内逐步放量；参考 claude.com/blog/projects-redesigned

为什么值得你花时间

你正在搭 agent 编排，「多个 agent 并行干活、上下文怎么对齐、冲突和依赖谁来收」是绕不开的一题，这条给的是官方正在跑的做法——Coordinator + 独立分支 + 共享记忆，连失败面（成本、合并冲突仍需人来把关）都写清了。花 15 分钟对照它的调度模型与权限设计，能直接回答你画布与成片链路里「哪些步骤该拆给并行 agent」。
