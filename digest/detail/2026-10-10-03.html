Qwen-Image-2.1-Turbo：8 步加速版，采样表被写进了权重

Qwen 官方 8 步加速图像模型，出图与改图同一份权重。
模型 15 分钟（读模型卡与价格；真跑走百炼 API，自托管需源码版 Diffusers） hf-org:Qwen

摘要 · 译自原文

Qwen 团队在 2026-10-09 放出了 **Qwen-Image-2.1-Turbo**，是 Qwen-Image-2.1 的加速 checkpoint，不是新架构、也不是新模型族：仓库元数据把它标成 `base_model: Qwen/Qwen-Image-2.1` 加 `base_model:finetune`，也就是厂商自己把它描述成基线的微调版本。它用同一个 7B 视觉生成组件（单流 DiT、32 层、block-causal attention——文本 token 走 token 级因果掩码、图像走 chunk 级双向掩码），配 **Qwen3-VL 8B** 文本编码器编码指令与条件图，VAE 是 64 通道 RGBA 自编码器、16 倍空间压缩，因此原生支持透明通道；调度是 Flow Matching + Euler 离散。变化是把去噪步数从基线示例用的 **40 步压到 8 步**，默认 **CFG=1**（不做无分类器引导，这也是轨迹能被大幅缩短而不崩的原因之一），并用 prefix KV cache 在去噪步之间复用文本与参考图上下文——8 步的循环里，缓存覆盖了大部分条件计算成本。分辨率沿用基线全部 7 档（2048×2048、2400×1792、1792×2400、2528×1696、1696×2528、2752×1536、1536×2752），能力覆盖文生图与指令编辑，展示按 8 类组织（人像、人体姿态、透明 RGBA、字体与海报、UI 与信息布局、单图变换、多参考合成、四图室内合成）。

真正的技术变化不在步数，而在**采样表被搬进了权重**。模型卡写明：推荐的 8 步采样调度随 checkpoint 保存并自动加载，**只设置 `num_inference_steps` 不能覆盖它**——你可以传任何整数，pipeline 仍然用保存好的那份调度；唯一的覆盖方式是调用时显式传 `sigmas`，而模型卡补充说其他调度「尚未评估」。这打破了很多人的 Diffusers 直觉（步数是调用时参数），所以会出现一个复现陷阱：把 Qwen-Image-2.1 模型卡里的示例代码改成指向 Turbo 仓库，**跑得通、不报错、但产出不是展示图那批效果**。配套的安装条件也偏新：需要一个能理解 pipeline 级配置 sigmas 的 Diffusers 构建（PR #14950，写作时还在源码树而不是 tagged release），加 `transformers>=5.17.0`、accelerate、pillow，以及 CUDA 版 PyTorch。

价格与许可是两个硬约束。阿里云百炼已经上线 `qwen-image-2.1-turbo`（**0.1 元/张、120 RPM**，北京 / 美国 / 德国 / 日本 / 香港同价，新加坡 0.113362 元/张）与 `qwen-image-2.1-pro`（0.25 元/张、20 RPM），Turbo 单价便宜 **2.5 倍**、速率高 **6 倍**。但权重仍按 **Qwen Research License Agreement** 分发（仓库 `license: other` + `license_name: qwen-research`），加速不改变许可，商用自托管要单独授权；想按 8 步落地产品，路径是买百炼的托管 API。最后，官方**没有给出任何 Turbo 的质量分**（全文唯一的分是基线模型自己的 Qwen-Image-Bench 60.28，厂商口径），也没有吞吐 / 延迟 / 显存数字（基线卡有内存优化章节，Turbo 卡没有）；发布形态也很低调——只有仓库、模型卡和一行 news list 公告，没有独立博客、没有 day-zero 的 ComfyUI / vLLM-Omni / SGLang / LightX2V 支持（那些都只对基线模型）。**（未能抓取原站，以下据可达的第三方报道与镜像代理；模型卡原文与权重今天打不开。）**

要点

  • 同一 7B 单流 DiT（32 层）+ Qwen3-VL 8B 文本编码器 + 64 通道 RGBA VAE（16x 压缩、原生透明），采样 **8 步 vs 基线 40 步**，默认 CFG=1
  • **采样表随 checkpoint 保存并自动加载，`num_inference_steps` 无法覆盖**，只能显式传 `sigmas`；需 Diffusers PR #14950（源码树，未进 tagged release）+ `transformers>=5.17.0`
  • 沿用基线 7 档分辨率（2048×2048 至 2752×1536），文生图与指令编辑共用一份权重，prefix KV cache 在 8 步之间复用文本 / 参考图上下文
  • 百炼定价：turbo **0.1 元/张、120 RPM**；pro 0.25 元/张、20 RPM → 便宜 2.5 倍、速率 6 倍
  • 许可：**Qwen Research License（非商用）**，加速不改变许可；Turbo 无质量分、无吞吐 / 显存数据，也没有基线的 day-zero 框架支持

为什么值得你花时间

图像生成是你平台调用最频繁的一环，这条同时给了更便宜的价格和一个会静默毁掉复现的坑。① **便宜但没分数**：0.1 元/张、速率 6 倍，草稿档可以整体往下压一档成本，但官方没给 Turbo 任何跑分，前几次必须在你自己那批分镜提示词上 A/B，不能按「加速版 = 同质量」假设。② **参数被模型接管要进验收清单**：步数从请求参数变成 checkpoint 元数据，以后每换一个蒸馏 / 加速权重，先确认哪些参数已经不由你控制。③ **许可先于性能**：Research License 意味着它不能直接进商用产品，要落地就走百炼托管 API 而不是自托管权重。④ 分清官方与社区：你 10-04 读过 Viggle 的 6 步蒸馏版，那是社区 Space；这版的意义在官方 API 定价、许可与生态位（模型卡里连 ComfyUI / vLLM / SGLang 的 day-zero 支持都没有，那些只对基线模型）。**今天可做**：同一批提示词在 turbo 与 pro 上各跑一遍，比的是「单价差」和「需要重抽几次」。
