chrome-devtools-mcp：AI 报的性能数字可信，裁决还得自己来

让 AI 用 DevTools 采网页性能并出报告。
中文 15 分钟（已有 Chrome + 一个页面） cn:juejin

摘要 · 译自原文

chrome-devtools-mcp 是一个 MCP（Model Context Protocol，让编程助手接外部工具的协议）服务器，在支持 MCP 的客户端里加一行 `npx -y chrome-devtools-mcp@latest`，AI 就能拿到整套 Chrome DevTools 的 33 个工具：导航、点按、拖拽、填表、模拟设备、跑 Lighthouse（网页质量评分工具）、录 performance trace（浏览器记录的性能时间线）、翻网络请求、读控制台、抓堆快照等。文章作者没有预设指标，只给 AI 一个任务「对掘金首页做一次加载性能体检」，然后拿原始 trace 逐条核对。

第一轮就撞上环境问题：容器里是 root 用户，Chrome 拒绝启动，报 `Target closed` 和 `chrome-devtools-mcp is running as root`。AI 重试、换入口、三次确认后判定环境级故障，交了一份「一个指标都没拿到、本报告不含推测数值」的报告，还指出任务里要求调用的 `submit_report` 工具根本不存在。作者认为这次「拒绝编造」的行为本身值钱。修复是给 server 加 `--chromeArg=--no-sandbox` 和 `--chromeArg=--disable-dev-shm-usage`；另外视口参数要写 `1440x900`，用逗号会报格式错误。

第二轮跑通：10 轮模型调用、18 次工具调用、181,312 prompt tokens，冷加载 trace 24.3 秒落盘。AI 下钻了 LCPBreakdown、LCPDiscovery、ImageDelivery、ThirdParties、RenderBlocking、ForcedReflow、DOMSize、NetworkDependencyTree 八个 insight，翻了 181 条网络请求，还自己写了两段 `evaluate_script` 做交叉验证。报告给出 LCP 8956ms，分解为 TTFB 134ms、加载等待 7817ms、加载 48ms、渲染 956ms，四项加起来 8955，和 LCP 基本闭合；CLS 0.02、FCP 816ms；三张首屏封面图 1317/780/765KB，源分辨率 2596x2160 渲染成 71x40，单边 36 倍冗余；ImageDelivery 算出单次首屏可省 4MB。

作者写脚本解析 3.7MB 的原始 trace，逐条核对报告里的数字：LCP 时间戳、CLS 求和、三张图大小、byteimg 域 4.1MB、2596x2160 的源尺寸，全部对上；连「请求数 181」和 trace 窗口内 138 的口径差异，AI 也如实标注了。唯一翻车在判读：AI 说 LCP 图是 JS 在 7.95 秒创建的，trace 里发起者其实是 HTML parser；它自己发现过 LCPDiscovery 与 RenderBlocking 两条 insight 互相矛盾，但在裁决时选错了边。作者因此得出结论：数字层可以信，结论层必须自己拿原始 trace 验；另外单个工具输出要截断（他截到 8000 字符），否则上下文会爆。

要点

  • MCP 服务器，一行 `npx -y chrome-devtools-mcp@latest` 接入 33 个 DevTools 工具：导航、点击、Lighthouse、performance trace、网络请求、控制台、堆快照。
  • 容器内 root 起不来，加 `--chromeArg=--no-sandbox` 与 `--chromeArg=--disable-dev-shm-usage`；视口格式是 `1440x900`。
  • 第二轮 10 轮模型调用、18 次工具调用、181K prompt tokens；LCP 8956ms（TTFB 134 + 等待 7817 + 加载 48 + 渲染 956），CLS 0.02。
  • 三张封面图 1317/780/765KB，2596x2160 渲染成 71x40；单次首屏可省 4MB；181 条请求。
  • 数字全部经 3.7MB 原始 trace 核对；但 LCP 图发起者判读错了（parser 误判为 JS），结论必须人工复核。

为什么值得你花时间

你平台上「AI 说页面慢」和「AI 说改完了」一样，最缺的是可复核的证据链；这条给了一个能直接抄的验证姿势：让 AI 把 trace 落盘，再拿 trace 对它的每个数。今天拿你自己的一个页面跑一遍，重点看两处：它会不会主动写脚本交叉验证、结论和原始 trace 冲突时它选哪边（作者那次就选错了 LCP 图的发起者）。边界：需要 Chrome 稳定版或 Chrome for Testing；容器里用 root 用户（最高权限）起不来，要加 `--no-sandbox`；视口（浏览器窗口尺寸）格式是 `1440x900` 不是逗号；单个工具输出要自己截断（作者截到 8000 字符），否则上下文会爆；数字可信不等于结论可信。
