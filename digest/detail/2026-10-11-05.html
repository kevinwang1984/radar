AppAgent 源码拆解：结构定位、视觉决策，以及网格兜底里的一个静默 bug

安卓 GUI Agent 源码拆解，含一个静默 bug。
中文 1 小时（读拆解；真跑要 Android 设备 / 模拟器 + adb + 一个多模态模型 key） cn:juejin

摘要 · 译自原文

这是「LLM 驱动的自动化测试」系列的第 8 篇，作者冬奇Lab 没有复述论文，而是逐段读腾讯 **AppAgent**（CHI 2025、arXiv:2312.13771、MIT、官方仓库 `TencentQQGYLab/AppAgent`）的源码，回答三个问题：解析树 + 视觉双输入到底怎么运作、比纯视觉 / 纯坐标方案在精度与成本上如何取舍、解析树失效时怎么退化。第一个纠正很关键：**解析树不是第二个模型，只是一份确定性的 XML**。`and_controller.py` 的 `traverse_tree()` 遍历 `adb shell uiautomator dump` 下来的 UI Automator 树，抓出所有 `clickable="true"` 与 `focusable="true"` 的节点记录边界框，两类节点分别遍历一次后用欧氏距离阈值（`config.yaml` 里的 `MIN_DIST: 30`）去重，去重后的元素交给 `draw_bbox_multi()` 在截图上画数字标签（可点标红、可滚标蓝）——这张「贴了数字的截图」才是喂给模型的输入。提示词里的动作空间只有 `tap(element)` / `text(element, text_str)` / `long_press(element)` / `swipe(element, direction, dist)` / `grid()`，**几乎所有动作的第一个参数都是数字标签，不是坐标、不是元素路径**：模型只需要「看图选数字」这种更弱的视觉能力，定位精度被前置到运行时的确定性代码里，代价是鲁棒性完全绑定在 Android 无障碍框架暴露的信息上。元素身份由 `get_id_from_element()` 生成：优先用清洗过的 `resource-id`，没有就退化成 `class_宽_高`，可选拼一段截断的 `content-desc`；这个 `uid` 是所有文档持久化的主键——**同一元素在不同截图里换了位置仍能命中同一份笔记**。

探索阶段是 act-then-reflect 循环：每轮先截图、解析元素、让视觉模型选一个动作执行，再截一张「动作后」的图，把前后两张一起交给同一个模型反思，要求输出四选一——`SUCCESS`（达到预期）、`BACK`（去了错误的地方，会真的调 `controller.back()` 撤销）、`CONTINUE`（界面变了但没帮上任务，不撤销）、`INEFFECTIVE`（界面没变化）。只有 `INEFFECTIVE` 不生成任何文档，其余三种都会为该元素写一段自然语言文档；更有意思的是**主动剪枝**：判定为 `INEFFECTIVE` 或 `BACK` / `CONTINUE` 的元素 `uid` 会被记进 `useless_list`，后续每轮直接跳过，把有限的探索轮次（`MAX_ROUNDS: 20`）留给没验证过的元素——反思在这里不只是「要不要重试」，而是**决定探索空间本身会不会收缩**。两条清晰的能力缺口：自主探索**永远不给文本输入框生成文档**（主循环里 `elif act_name == "text": continue`，`text_doc_template` 只被人类演示路径 `document_generation.py` 引用），而只有 App 的关键交互依赖搜索框 / 登录表单时，这个缺口会直接卡住任务；此外**只有人类演示路径支持 `DOC_REFINE` 文档精修**（开启后把新观察与旧文档合并重写），自主探索是「先到先得、写一次就不再更新」。

网格兜底是解析树失效时的退化方案（WebView、自定义渲染控件、游戏画面不会出现在无障碍树里，`traverse_tree()` 枚举不到），提示词里明确告诉模型：想操作的元素没有被标数字、且标了数字的元素都帮不上忙时，就调 `grid()`；调用后 `grid_on` 只对下一轮生效，`draw_grid()` 在截图上叠一层网格（单元格尺寸取落在 [120, 180] 像素区间的整数因子，找不到就固定 120），模型改用 `tap_grid(area, subarea)` 这类动作，`subarea` 从九个命名方位里选。作者指出两个问题：第一，**动作空间发生了收缩而不只是精度下降**——网格模式的提示词模板里根本没有 `text()`，一旦退化到网格，模型就彻底失去输入文本的能力；第二，兜底路径里有一个真实存在的坐标 bug，就在 `and_controller.py`：`swipe_precise()` 拼 adb 命令时写成了 `... input swipe {start_x} {start_x} {end_x} {end_y} ...`，第二个本应是 `start_y`，导致滑动起点 Y 坐标取的是 X 的值；而全库 `swipe_precise` 只有一处调用——`task_executor.py` 第 275 行的 `swipe_grid` 分支，也就是说这个 bug **只在网格兜底这条已经降级的路径上、不报错地**从错误的 Y 坐标开始滑。文章还记了几处工程痕迹：三个响应解析函数共用同一种非贪婪、匹配到行尾的正则，字段内容跨行会被静默截断；解析失败走裸 `try/except` 返回 `["ERROR"]` 哨兵，主循环检测到就直接 `break` 结束整个任务（没有重试、没有格式纠错）；成本估算硬编码了 GPT-4V 时代的费率、与实际配置的 `gpt-4o` 脱钩；截图实际是 PNG 却按 `image/jpeg` 的 MIME 发给接口。README 只说明评测集是 9 个 App / 45 个任务（指向 `assets/testset.md`），**没有给出任何成功率数字**，文章据此不做数字引用。

要点

  • 双输入的真实分工：解析树只是确定性的 XML（`uiautomator dump` → `clickable` / `focusable` 边界框 → `MIN_DIST: 30` 去重 → 截图上贴数字标签），**决策 100% 由单个视觉模型基于「贴数字的截图」完成**，动作参数是「选哪个数字」而不是坐标
  • 元素身份 `uid`（优先 `resource-id`，退化为 `class_宽_高` + 可选 `content-desc`）：文档按身份持久化而非坐标，元素换位置仍命中同一份笔记
  • 反思四分类 `SUCCESS / BACK / CONTINUE / INEFFECTIVE`；`INEFFECTIVE` 不产文档，且被判失败的元素进 `useless_list` 被**主动剪枝**，探索预算（20 轮）留给未验证元素
  • 两个能力缺口：自主探索**从不给文本输入框生成文档**（`elif act_name == "text": continue`）；**只有人类演示路径有 `DOC_REFINE` 精修**，自主探索写一次就不再更新
  • 网格兜底 `grid()` 的两个问题：**动作空间里直接没有 `text()`**（整类操作消失）；`swipe_precise()` 里起点坐标误写为 `{start_x} {start_x}`，且只被 `swipe_grid` 调用——静默地从错误 Y 坐标起滑
  • 其他工程痕迹：三处响应解析共用会静默截断多行的正则、解析失败即终止整个任务无重试、成本估算硬编码过时费率且与配置模型脱钩、PNG 截图按 JPEG 的 MIME 发送；README 未给成功率（评测集为 9 个 App / 45 个任务）

为什么值得你花时间

① 这是「让模型操作界面」里最省的一种架构选择：**把需要精确坐标的部分交给确定性代码，把需要理解的交给模型**——模型只需要「看图选数字」这种更弱、更稳的能力，不必训练专用的 grounding 模型。你的画布 / 后台如果要做自动化操作，这条分工比自训一个坐标模型便宜得多。② 两个可直接抄的决策：**文档按稳定身份（`resource-id`）存而不是按坐标存**；**反思结果反过来收缩探索空间**（把已验证没用的元素拉黑，而不是只决定要不要重试当前动作）。③ 两处要引以为戒的失败模式：兜底路径会**静默地把一整类能力从动作空间里删掉**（网格模式下没有输入文本），以及**解析失败即终止整个任务、没有重试与格式纠错**——你的 Agent 输出解析器同样要回答「格式不对时是重问一次还是整个任务死掉」。④ 那个坐标 bug 的形态很典型：只读代码看不出来、只在降级路径上触发、不报错只是结果不对——与你 10-10 读过的「毒标记」「稀疏抽样不能证明完整性」是同一类静默损坏。**今天可做**：把你 Agent 的兜底分支单独跑一遍（而不是只测主路径），看兜底时哪些能力静默消失了。
