高效电商 AI 智能体解剖指南

Anthropic 拆解电商 agent 的架构、延迟与评估。
跟人 15 分钟 people:baoyu

摘要 · 译自原文

Anthropic 官方博文《A guide to the anatomy of effective commerce agents》的中译（宝玉译，2026-09-02）。文章基于一年里与零售商、电商平台、旅游娱乐电信客户的合作，给出一套已在生产运行的电商 agent 架构：把一个模型放在标准 agent 循环里，用技能覆盖长尾，用工具去调用你已有的搜索排序、购物车、库存、促销、分析系统。它明确反对「每个垂直领域一个子智能体」：每次交接都是丢状态的操作，会同时损失回复质量、多烧几倍 token、增加几秒延迟；正确做法是单一 agent 加技能做模块化，子智能体只留给需要独立上下文窗口的深度研究这类任务。提示词与技能的分界按使用频率定：与三分之一以上流量相关的指令进系统提示词，安全与法律底线永远进提示词，其余长尾做成技能。

工程细节很密：工具返回结果即上下文，只回推理需要的字段（典型反面是每条结果都带长图片 URL），错误要给明确指令而不是裸 403；把每个 UI 组件做成工具（`present_products` / `present_itinerary` / `present_plan_comparison`），格式由服务器验证、历史记录也天然可重放，还让模型知道用户说的「第一个酒店」是哪个；延迟要同时优化端到端与感知两端（提前预载上下文、并行调用、参数流完就急切分发），提示词缓存把读取成本降到 1/10，做得好的电商部署命中率 90–99%；记忆放自己的数据库、异步写入、分三层读取（常挂上下文 / 每轮预取 / 查询工具）；安全由 Harness 在代码层兜底，下单与改价只能生成带服务器 ID 的暂存更改、批准后才 apply，所有第三方内容一律当不可信输入净化；评估评快照状态而非路径，并给每个正向用例配反向雷区用例，上线要灰度、留一键关技能的开关。文末给了参考实现 github.com/anthropics/commerce-agents。

要点

  • 单 agent + 技能 > 每领域一个子 agent：交接丢状态、token 翻倍、多几秒延迟
  • 指令分界：与 ≥1/3 流量相关的进系统提示词，长尾做技能，安全底线永远在提示词
  • 把 UI 组件做成工具（present_products 等），格式由服务器保证，也解决「第几个」的指代
  • 提示词缓存读取成本约为全新输入的 1/10，成熟电商部署命中率 90–99%
  • 安全靠 Harness：写入只能是带服务器 ID 的暂存更改，审批后 apply_change；第三方内容必须净化
  • 评估评快照不评路径，每个正向用例配一个反向雷区用例；参考实现 github.com/anthropics/commerce-agents

为什么值得你花时间

你正在搭的正是「一个 agent + 一批技能 + 一批工具」的内容平台，这篇等于把 Anthropic 在电商场景踩过的坑列成清单——延迟预算怎么分、技能与提示词怎么切、钱和安全的边界画在哪，读完可以直接对着自己的架构改一版。
