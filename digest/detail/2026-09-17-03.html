Jev（TypeSafe System One Models）

只做判断、不写文字的分类路由模型，成本极低。
跟人 需要申请 key（early access） people:latent-space

摘要 · 译自原文

TypeSafe（CEO 是 ChatGPT 共同作者 Diogo Almeida）在 9 月 15 日发布 System One Models 与新模型 Jev，训练方式叫 RLCD（calibrated decisions）。它的立论是：LLM 本质是为「给人读的文本」设计的，一旦你要的是「给代码消费的判断」，就变成了把文本生成系统硬掰成结构化输出再解析回来——Jev 直接把这一步去掉。

官方文档写得很直白：Jev 接收状态（state）与类型化问题（typed questions），返回结构化结果，**不做文本生成、不需要解析**，给出的是类型化取值与概率分布，代码可以直接分支、排序、路由。它提供三种原语：Choice（从列表里选，返回 choice / probabilities / confidence）、Score（按 rubric 打分）、Noul（判断命题真假，返回 0–1）；三种可以混在同一次调用里，各问题**并行且相互隔离**地对同一状态求值，因此多问几个问题几乎不增加响应时间，也不会有上下文腐化的相互干扰。官方建议把它当「几秒钟内能做出的gut-check判断」，复杂判断先拆成若干原子问题、再用代码里的权重合成。

成本与速度的口径：每百万输入 token $0.042，输出被记作「$0 / 低到不可测量」；推文与二手报道称其快 20–200 倍、便宜 40–400 倍，在同等任务质量（对标 GPT-5.6 Terra）下成本约为 1/100。工具调用错误率为 0%，所有输出都带置信度。代价同样被官方承认：Jev 不能生成自由文本。目前走 early access 申请制，文档与 quick start 已公开。

要点

  • 输入 $0.042 / 百万 token，输出近乎不计费；官方称同等质量下成本约为 GPT-5.6 Terra 的 1/100
  • 20–200 倍更快、40–400 倍更便宜（推文口径）；工具调用错误率 0%，输出带置信度
  • 三种原语：Choice / Score / Noul，可混在一次调用里并行求值，加问题几乎不加时间
  • 返回 typed 值与概率分布，不需要解析文本；代价是不能生成自由文本
  • early access 申请制，文档：https://docs.typesafe.ai/introduction

为什么值得你花时间

你的 agent 链路里有一大堆「不值得让前沿大模型写一段话」的判断——意图分类、工具路由、结果打分、质检门、是否重试。把这些从「先生成再解析」换成 typed 返回值，是省钱也是减少一类长尾故障；这两天就能拿 early access 文档里的 Choice / Score / Noul 和现有 prompt 逐条对照，周末试着把最贵的一条判断换掉。
