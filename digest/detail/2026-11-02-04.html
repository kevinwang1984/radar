remove-animations：给界面动画做一次减法评审

逐个审判界面动画，删掉站不住脚的那些。
其他 15 分钟（装技能 + 对一个页面跑一轮 sweep / gate） weekly:skills-sitemap-diff

摘要 · 译自原文

`remove-animations` 是 Emil Kowalski 的减法技能，只做一件事：把界面里现有动画逐个送上「审判」，删掉或减弱站不住脚的那些，再清掉因此孤立的 keyframes、`AnimatePresence` 包装和 import。它不新增动画，也不修缓动、origin 或可中断性；那些属于 `improve-animations` 和 `review-animations`。它的出发点是 Emil 的《You Don't Need Animations》：Agent 默认爱加动效——滚动 fade-in、卡片 hover 放大、命令面板开合——每个单看都合理，叠起来就是「慢」。所以它把举证责任反过来：动画要自己证明为什么留下，「已经在这」和「好看」不算理由；但也不能一刀切删光，能桥接突兀变化的动效（比如 toast 从底部进入、面板要说明从哪里来）应该保留。

判定树写得很具体：键盘触发的动画直接删（Raycast 没有开合动画，就是最优体验）；每天见 100+ 次的动画直接删（任何时长都会被读成延迟）；功能性数据（图表、表格、数字、仪表盘）上的动画直接删，除非它展示的是用户动作带来的真实数值变化；说不出目的的，只有「罕见的一次性时刻」才留（onboarding、空状态、成功），其余删；有目的但每天见几十次的（hover、频繁切换、列表展开）减到近乎无感；超过 300ms 或「滑动 / 缩放能用淡入表达同样意思」的也减。减弱只做同一种动效的小版本：hover 缩放 / 抬升 / 阴影改成颜色或透明度 ≤150ms；高频表面的滑动 / 缩放入场改成 150ms 淡入；超过 300ms 的压到 200–250ms；stagger 每项 ≤30ms 或整组一起淡入；常驻无限循环改成只跑一次或保留静态终态。

它还列了「哪里找」和「删之前查什么」。常见目标包括快捷键打开的命令面板 / 菜单、标签切换、侧边栏导航、路由过渡、列表 hover 变换、每节都在的滚动 reveal、非主操作的卡片 hover 放大、常驻无限循环、图表每次 mount 从零重画、页面加载时数字 count-up、表格行动画、<300ms 操作的 spinner / skeleton、`transition: all`。删除前必须查：从 `opacity: 0` 起步的 hidden start state（删动画不删起始态会让元素永久不可见）、等动画结束的 `onAnimationEnd` / `transitionend` / `setTimeout`、`AnimatePresence` 的卸载延迟、用 layout / FLIP 掩盖的布局跳动、在动画回调里移动的焦点、依赖动画类或时长的测试。输出强制包含三部分：删 / 减表（带 `file:line` 和判定分支）、保留的 2–5 个动画及理由、清理与真机手感待查项。

要点

  • 9.3K 安装；仓库 52.7k 星；2026-10 底首次出现
  • 只做减法；不新增 / 不调缓动；卸载动效库要先提议，不擅自动 lockfile
  • 判定：键盘触发、每天 100+ 次、功能性数据直接删；有目的 + 低频才留；高频减到近乎无感
  • 减弱：hover 只改颜色 / 透明度 ≤150ms；UI 动画 >300ms 压到 200–250ms；stagger ≤30ms
  • 删除前查 hidden start state、`onAnimationEnd`、`AnimatePresence` 卸载、layout 跳动、焦点、测试

为什么值得你花时间

你的画布 / 工作流界面是高频操作面，Agent 又天然爱加 fade-in、hover-scale、路由过渡；这类动画单个看都合理，叠起来就是「慢」。这条技能的价值是反过来举证：动画要自己证明为什么留下，而且明确要求列出「保留的 2–5 个及理由」，避免一刀切删光。**今天就能做**：对画布页面跑一次 recon + sweep，先只处理键盘命令面板、标签切换和列表 hover 三类，15 分钟能看到手感差异。边界：它不改缓动 / origin / 可中断性，也不判断真机手感；删之前要查 hidden start state、`onAnimationEnd`、AnimatePresence 卸载延迟这些坑。
