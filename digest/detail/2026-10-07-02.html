万物皆插件：一篇把 dsh 的机制与小字条款一起讲透的拆解

讲清 dsh 插件机制与 token 代价的深度拆解。
中文 15 分钟（只读「日志即真相」与「小字条款」两节；照它的 4 小时路径走一遍约半天） cn:juejin

摘要 · 译自原文

这是一篇对 DeepSeek Harness（`dsh`）的体系化拆解（作者 MobotStone，10-06），写作动机很明确：围绕 dsh 的报道多在讨论理念与战略，**真正讲内部机制的并不多**，而它的「说明书小字」是最容易被热度掩盖的部分。文章把 dsh 与过去二十多年那类「固定的坚硬核心 + 外围扩展点」的 Agent 框架做了逐项对比：在 dsh 里**不存在特权核心**，Agent Loop 本身（`packages/core/agent-loop`）就是一组普通插件，改调度逻辑只需改 YAML；模型适配器、沙箱（Linux Landlock / macOS Seatbelt / Windows 受限 Token / 远程）、会话存储、文件系统抽象、任务调度器、Web UI 全部是插件；连 **Sub-Agent 也是 provider**，可以直接把 Claude Code 或 Codex CLI 当 worker 调度（用你自己的账号认证）。作者引用的一个比喻很贴切：Codex 是精装房附一面洞洞板，而 dsh 是把整栋房子连同图纸交给你，允许你在不拉闸、不断水的前提下拆改任意一面承重墙。

机制部分最扎实的是三节。**Cordis 组合层**（DeepSeek 与北大联合开发，主打「时空可组合性」）在工程上保证两件事：空间维上插件用 `inject = ["tools"]` 声明依赖、把服务与事件监听器注入共享 context，运行时自动解析顺序；时间维上每个副作用都注册 disposer（`ctx.effect()` 返回 undo），**因此可以在会话执行到一半时卸载当前沙箱、动态挂载新的，完全不用重启**。一个最小插件只有 8 行。**会话日志即真相**：dsh 强制执行「模型可见，即被记录」——任何进入上下文的内容（system prompt、思维链、工具调用与返回、子 agent 调度指令、每一次上下文注入）都写进 append-only 日志，而 Resume / Fork / Replay / 历史搜索 / Trajectory 视图全都从这条事件流派生；**日志不是运行的副产品，日志就是运行的实体**。值得注意的是它**完全保留思维链**，与部分西方实验室为防蒸馏而加密思考过程的路线相反。**工具执行管道**是「预执行校验 → 权限处理 → 执行 → 后处理（敏感信息掩码与结果验证）→ 结果持久化落盘」，每阶段可插 hook；并在 schema 层把 **Approval（这个操作需要人类点击确认吗）与 Sandbox（这个操作物理上最高能触及哪些资源）**明确分开——文档原话是「弹窗确认并不等于文件系统的安全边界」。此外还有四种默认工作模式（Standard / Code Mode / Minimal / Creator），其中 Code Mode 把工具封装成 TypeScript SDK，模型不再一次次单调用而是写一段脚本批量执行；Creator 模式下 agent 能用默认关闭的 `cordis_*` 工具**自己写插件扩展自己**。

「小字条款」部分是全文最值钱的地方：社区早期测试显示 dsh 的 **token 用量约为极简 harness Pi 的 10 倍、其他主流框架的约 3 倍**；已确认的 bug 之一是把内容相同的 `CLAUDE.md` 与 `AGENTS.md` **重复注入两遍**，导致这段 system prompt 直接翻倍；ISS Tracker 案例里两轮长交互约 35 分钟、累计消耗接近 **2000 万 token**（靠 95%–100% 的缓存命中率才没失控）；第三方插件状态是「**41 个确认可用、219 个尚待验证**」，而两周内出现了约 **2000 个社区插件**。作者的结论并不激进：现阶段没理由为了架构优雅把核心业务切过去，Claude Code 与 Codex 的完成度和 token 效率仍然更好；但即使不用 dsh，也有四个设计值得抄走。

要点

  • 核心命题：dsh 把「固定的坚硬核心 + 外围扩展点」翻转为**没有特权核心**——Agent Loop、模型、沙箱、上下文组装、Session、Web UI 全是可替换插件
  • Cordis 引擎：`inject` 声明依赖（空间维）+ `ctx.effect()` 注册 disposer（时间维）→ **可在会话中途热插拔、无需重启**；最小插件 8 行
  • **日志即真相**：模型可见即被记录，append-only；Resume / Fork / Replay / Trajectory 全部由事件流派生；**不经压缩地保留完整思维链**
  • 权限模型：**Approval（人要不要确认）与 Sandbox（程序实际能碰什么）在 schema 层分离**——「弹窗确认并不等于文件系统的安全边界」
  • 可换部件清单：Agent Loop（含 `plan-act-verify` 等）、模型 provider（DeepSeek / OpenAI / Anthropic / Bedrock / Vertex / Azure / 本地）、沙箱（Landlock / Seatbelt / Windows 受限 Token / 远程）、**Sub-Agent provider（可调度 Claude Code、Codex）**
  • 代价（官方不会写在首屏）：**token 用量约为 Pi 的 10 倍、主流框架的约 3 倍**；`CLAUDE.md` 与 `AGENTS.md` **内容相同时被重复注入两遍**、system prompt 翻倍
  • 实测极端案例：ISS Tracker 项目两轮长交互约 35 分钟、接近 **2000 万 token**，缓存命中率 95%–100%
  • 生态数字：两周约 **2000 个社区插件**，兼容状态 **41 个确认可用 / 219 个尚待验证**
  • 可抄走的四个设计：**日志就是运行本身** / **审批与沙箱分离** / **Code Mode 批量执行工具** / **按 session 动态选模型与推理强度**
  • 4 小时上手路径：看 Trajectory → 换 Minimal 模式与模型 → 从历史节点 Fork 改决策重跑 → 写一个 8 行插件 + 读 `.agents/` 里 3 条架构决策记录
  • 核验口径：**【原站核验】** `juejin.cn` 可达、全文已读（部分小节因抓取长度被截断）

为什么值得你花时间

你每天跑的就是 dsh，而这篇文章给的是官方 README 不会写的东西：**账单的形状，和几个具体的设计判断**。「`AGENTS.md` / `CLAUDE.md` 双注入」这条对你尤其直接——你的 `~/.dsh/AGENTS.md` 里有一整套执行边界规则，如果两个文件内容相同，这段 prompt 会被算两遍、白烧一份 token；**值得今天就检查你是不是同时在维护内容重复的两份**。四个可以直接搬走的设计：① **日志就是运行本身**（你已经在读会话记录，但「模型可见即被记录」是更强的约束——它是审计、重放与 Fork 的前提）；② **审批与沙箱必须分开**（弹窗确认不等于文件系统边界，这条你已经做对，但它把理由讲透了）；③ **Code Mode**：与其让模型连续发起十几次零散工具调用，不如生成一段受控脚本批量执行；④ **按 session 动态选模型与推理强度**，而不是全局一个默认值。它还给了今天就能照着做的 4 小时路径：先跑 Standard 模式只看 Trajectory（Harness 到底给模型看了什么）→ 同任务换 Minimal 模式与另一个模型 → 从历史节点 Fork 改一个决策重跑 → 写一个 8 行插件。**结论部分它也说了实话**：现阶段没理由为了架构优雅把核心业务切过去，Token 开销与预览版接口变动是实打实的「预览版税」。
