01 External Sandboxes：把 coding agent 关进可审计的 Linux 沙箱 把 Agent 关进可审计的 Linux 沙箱。 跟人 1 小时 people:simonwillison ›
是什么Prime Radiant 开源的三套 external sandbox 原型：`external-sandbox-v86`（Node.js + v86/WebAssembly 跑 Alpine）、`external-sandbox-container`（Apple Containers）、`external-sandbox-quicksand`（Microsoft Quicksand + QEMU）。三者实现同一套 localhost 协议，可以混用 Claude Code、Codex 和 Pi；agent 仍在你机器上跑，只把命令发进沙箱。沙箱只看到你挂载的目录，默认没有外网；加 `--proxy` 后按 host + HTTP 方法白名单放行，并支持 credential replacement（真实 key 留在宿主机，沙箱里只有占位符）。两条命令就能试：先 `npx --yes external-sandbox-v86 --preserve-paths --mount-rw "project=$PWD"`，再用 `npx --yes @earendil-works/pi-coding-agent -e npm:external-sandbox-pi --no-builtin-tools --sandbox-url http://127.0.0.1:8686` 起 Pi。 为什么值得你花时间你在 Gitea 上跑 wayfinder、还会给画布 agent 开浏览器和沙箱，现在这些权限散落在 shell 历史、控制台看板和记忆里；这条把「能读哪些目录、能访问哪些域名、能拿到哪些凭证」变成可审计的边界，而且不依赖模型自己判断该不该做。今天可以用 v86 + Pi 跑一个 hello 项目，再把 `--proxy-config` 指到 GitHub API 的只读白名单，看 agent 能不能在不暴露 token 的情况下拉 issue。边界：三套都还是实验原型，明确说没做安全审计；沙箱是 Linux，macOS 的 `node_modules` / `.venv` 要在里面重装；Claude Code 只有 Bash 走沙箱，原生 Read/Edit 仍在宿主机；Codex 的 exec-server 协议是实验性的，其他版本要自测；读写挂载仍可能被 agent 破坏，重要目录用 `--mount-ro`。 上手成本1 小时（Node 22.19+，跑通 v86 + Pi） 入口https://blog.primeradiant.com/external-sandboxes-for-coding-agents/ （仓库 https://github.com/prime-radiant-inc/external-sandbox） 读详情（翻译 + 要点）→

04 Alloy CSS：关掉 JavaScript 也能用的弹窗、菜单和标签页 一份 CSS 让弹窗菜单在关掉 JS 时也能用。 小而美 15 分钟 hn:show ›
是什么Fandy Pradana 的 MIT 开源 CSS 库，一份 stylesheet 覆盖按钮、表单、表格、对话框、菜单、抽屉、tabs 和 toast；对话框就是 `<dialog>` + 一个指定它的按钮，菜单用 popover，不靠 JS 打开。没有构建步骤，CDN 一行 `<link>` 即可，适配 Rails / Django / Laravel / htmx，也能在 React / Vue / 纯 HTML 里用；自带两套暗色主题，按 `prefers-color-scheme` 切换。它还为 AI 准备了 `llms.txt` 和 `npx @alloyhtml/css skill`，`npx @alloyhtml/css check app/` 会抓出 AI 编造的 class（示例里 `.mt-4`、`.btn`、`.btn-primary` 三个都不存在）。 为什么值得你花时间你的画布设置页、素材库、任务列表这类「服务端渲染 + 少量交互」的界面，最容易被组件库和构建链拖慢；Alloy 把弹窗、菜单、开关、toast 做成无 JS 的 HTML 约定，AI 生成页面时 class 也收敛到一套，`check` 能当 lint 用。今天拿一个现有设置页或素材列表，按它的 class 重写一屏，关掉 JS 走一遍弹窗、菜单、tabs 和 toast，再跑一次 `check` 看 AI 会编出多少不存在的 class。边界：它要求浏览器支持 `<dialog>`、popover 等新特性（Chrome / Edge 135、Firefox 144、Safari 26.2 起）；复杂交互仍要自己写 JS；82 页模板是 $29 单独售卖；它是通用 UI 库，不解决画布节点、时间线这类专门交互。 上手成本15 分钟（一行 CDN + 打开 example.html） 入口https://alloyhtml.com/example.html （仓库 https://github.com/alloyhtml/css） 读详情（翻译 + 要点）→

06 Claude Code 团队的验证方法：让 Agent 用证据证明改对了 Claude Code 团队怎么让 Agent 自证改动。 方法 1 小时 hn:stories ›
是什么claude.dev 11-16 的工程文章（Addy Osmani），讲 Claude Code 团队怎么让 agent 用证据验证自己的改动：团队约 90% 的代码由 Claude 写和 review；内部测试里，一个独立 grader 按 rubric 检查能把任务成功率最多提高 10 个点；他们优先投资 E2E（真实用户流，失败能看到截图和步骤）、property（round-trip / invariant / idempotency / equivalence，用 fast-check / Hypothesis / proptest 生成上千输入）、differential（旧系统当 oracle，跑同一批输入）三类测试。流程上：`verify` skill 放在 `.claude/skills/`，提交前必须跑；检查失败三轮就停并交给人；39 条 reliability checklist 按 diff 触发，通常只查 3–10 条；review 只认 commit，不认过期 diff；规则文件从 base 分支读，改动不能修改自己的检查；commit gate 分 off / observe / enforce 三档。 为什么值得你花时间你在 wayfinder / 画布 agent 上迟早要把「改完自己验」变成默认流程；这条给的是可抄的验收结构：先写 E2E 的完成标准，再用 property 测边界，迁移类改动用 differential 对旧系统，最后把「review 改不了自己的检查」和「失败三轮找人」写进流程。今天挑一个你最近返工最多的仓库，加一个 `verify` skill（启动 + 一条真实用户流 + 截图 / 日志），再开 observe 模式的 commit gate 跑一周，看它能不能拦住「测试过了但功能坏了」。边界：文章是 Anthropic 团队自述，90% 和 +10 点都是内部口径；E2E 慢且可能 flaky，flaky 测试会训练 agent 重跑而不是修代码；property / differential 需要可生成的输入和旧系统；commit gate 的 enforce 会挡提交，先 observe；不是所有团队都有 39 条清单可抄。 上手成本1 小时（读 + 加一个 verify skill） 入口https://claude.dev/blog/how-the-claude-code-team-thinks-about-verification/ 读详情（翻译 + 要点）→
