06 Harness Engineering 入门：Agent = Model + Harness 把 agent 理解为模型加外围执行环境的方法论。 中文 15 分钟 cn:juejin ›
是什么一篇中文入门，讲透 LangChain 的 Vivek Trivedy 在 2026 年 3 月给的公式：**Agent = Model + Harness，如果你不是模型，你就是 Harness**。文章把 Harness 拆成七层——Instructions（CLAUDE.md / AGENTS.md / Skill 定义）、Knowledge（记忆、上下文压缩、检索、进度文件）、Tools（文件读写、Shell、搜索、MCP）、Infrastructure（沙箱、浏览器、执行环境）、Orchestration（子 agent、路由、上下文防火墙、权限门）、Hooks（确定性生命周期脚本）、Observability（日志、追踪、成本计量），并给出排查顺序：agent 出问题从第一层往下问「哪一层失败了」。最实用的一个坑是：CLAUDE.md 是作为上下文加载、不是作为配置强制执行的，上下文塞满时会被忽略，所以硬规则必须落到 Hook。 为什么值得你花时间你天天在写 skill、hook 和 AGENTS.md，却缺一个「哪层薄了就补哪层」的统一框架；这篇 15 分钟读完就能当排查清单用，也能解释为什么同一个模型在别人手里稳、在你手里要逐句补救。 上手成本15 分钟 入口https://juejin.cn/post/7685320540698624043 读详情（翻译 + 要点）→
07 Warp 如何让 Agent 自我进化 用人类评审评论自动迭代代码审查技能的闭环。 跟人 15 分钟 people:baoyu ›
是什么宝玉对 Claude 官方博文《How Warp builds self-improving agents on Claude》的解读。Warp 做 AI code review 时发现瓶颈不是模型能力而是**没有记忆**：agent 不了解项目、不知道团队规范和历史教训。解法是两个 skill 配对——一个做审查，另一个定期收集人类工程师在 PR 上对 agent 审查结果的评论，据此更新前者。关键是不让模型自我评判，而是**让 agent 根据人类的标注改技能**，且摩擦极低：人只要在本来就会写评论的地方写评论，收集与更新全自动。文末给了 6 条实践（写原则不写死规则、解释为什么、反馈零摩擦、skill 精简 + 渐进式披露、质量大于数量、「改进 skill 的 skill」可复用）和三道防跑偏的闸（限制谁的反馈有权影响更新、保留人工审核、有标准答案的领域先建验证基准）。 为什么值得你花时间你已经养着一批本地 skill 补丁，最大的风险就是没人给它们反馈、越用越旧；这套低摩擦循环可以照搬到你的 skill 库上，尤其是「谁能影响更新 + 人工审核」那道闸，正好补上裸补丁没有的保护。 上手成本15 分钟 入口https://baoyu.io/blog/2026-08-28/warp-self-improving-agents 读详情（翻译 + 要点）→
