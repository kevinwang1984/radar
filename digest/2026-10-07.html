是什么掘金长文（作者 MobotStone，10-06），对 dsh（DeepSeek Harness）做的体系化拆解，分三块。**机制**：底层是 Cordis 元框架（DeepSeek 与北大联合做，主打「时空可组合性」）——插件用 `inject = ["tools"]` 声明依赖、把自己的服务和监听器注入共享 context，运行时自动解析顺序（空间维）；每个副作用都注册一个 disposer（`ctx.effect()` 返回的 undo），所以**可以在会话执行到一半时卸掉当前沙箱、挂上新的，不用重启**（时间维）。会话层强制执行一条硬规则「**模型可见，即被记录**」：任何进入上下文的 system prompt、思维链、工具调用与返回、子 agent 调度指令、每一次上下文注入，都写进 append-only 日志，而 Resume / Fork / Replay / 历史搜索 / Trajectory 视图全都从这条事件流派生——**日志不是运行的副产品，日志就是运行的实体**。工具执行走「预执行校验 → 权限处理 → 执行 → 后处理（掩码与验证）→ 落盘」，每个阶段可插 hook，并在 schema 层把 Approval（人要不要确认）与 Sandbox（程序实际能碰什么）明确分开。**可换部件**：Agent Loop（含 `plan-act-verify` 这类替代）、模型 provider（DeepSeek / OpenAI / Anthropic / Bedrock / Vertex / Azure / 本地兼容接口）、沙箱（Linux Landlock / macOS Seatbelt / Windows 受限 Token / 远程）、上下文组装、Session 存储、Web UI，以及 **Sub-Agent provider——可以直接把 Claude Code 或 Codex CLI 当 worker 调度**。**小字条款**：社区早期测试里 dsh 的 token 用量约为极简 harness Pi 的 **10 倍**、其他主流框架的约 **3 倍**；已确认的 bug 之一是把内容相同的 `CLAUDE.md` 与 `AGENTS.md` **重复注入两遍**，导致这段 system prompt 直接翻倍；ISS Tracker 案例里两轮长交互约 35 分钟累计接近 **2000 万 token**（缓存命中率 95%–100% 才没失控）；两周内出现约 2000 个社区插件，而兼容状态是「41 个确认可用、219 个尚待验证」。**【原站核验】** `juejin.cn` 可达，全文已读（部分小节因抓取长度被截断）。 为什么值得你花时间你每天跑的就是 dsh，而这篇文章给的是官方 README 不会写的东西：**账单的形状，和几个具体的设计判断**。「`AGENTS.md` / `CLAUDE.md` 双注入」这条对你尤其直接——你的 `~/.dsh/AGENTS.md` 里有一整套执行边界规则，如果两个文件内容相同，这段 prompt 会被算两遍、白烧一份 token；**值得今天就检查你是不是同时在维护内容重复的两份**。四个可以直接搬走的设计：① **日志就是运行本身**（你已经在读会话记录，但「模型可见即被记录」是更强的约束——它是审计、重放与 Fork 的前提）；② **审批与沙箱必须分开**（弹窗确认不等于文件系统边界，这条你已经做对，但它把理由讲透了）；③ **Code Mode**：与其让模型连续发起十几次零散工具调用，不如生成一段受控脚本批量执行；④ **按 session 动态选模型与推理强度**，而不是全局一个默认值。它还给了今天就能照着做的 4 小时路径：先跑 Standard 模式只看 Trajectory（Harness 到底给模型看了什么）→ 同任务换 Minimal 模式与另一个模型 → 从历史节点 Fork 改一个决策重跑 → 写一个 8 行插件。**结论部分它也说了实话**：现阶段没理由为了架构优雅把核心业务切过去，Token 开销与预览版接口变动是实打实的「预览版税」。 上手成本15 分钟（只读「日志即真相」与「小字条款」两节；照它的 4 小时路径走一遍约半天） 入口https://juejin.cn/post/7693225151681396746 读详情（翻译 + 要点）→

是什么掘金文章（作者 老金带你玩AI，10-06），把 Karpathy 最近的用法讲成能直接执行的做法。要回答的问题不是「怎么让 AI 讲得更清楚」，而是：**AI 接手的工作越来越多之后，人怎么理解它交上来的东西**。Karpathy 给的路径是一路往外推——先把文字写清楚（他提到受控语言规范 ASD-STE100，要求少用模糊说法，并说自己有时只按约八成严格度执行），文字不够就出图，图不够就让模型生成 HTML 网页把交互加进去，最后才是定制讲解视频。文章最有说服力的一段是它对「更通俗 ≠ 问到卡点」的拆解：AI 说「访客到付费之间有几层转化」，每个词都认识，可哪个环节一动、最后会少多少付费用户，光读文字还是晕；这时继续让它解释漏斗，不如直接让它做一个能改三个数字的小网页（访客数 / 试用比例 / 付费比例），下面跟着显示每一阶段还剩多少人——把试用比例从 20% 改成 40%，最终付费人数从 20 变成 40，改一次数字看一遍结果，原本需要在脑子里同时记住的几层关系被搬到了眼前。文末给了一条重要提醒：**公式和结论仍要自己核对，别被漂亮动画带跑**；另外提到有人照这个思路做了一段 4 分 48 秒的 3b1b 风格随机微积分讲解，这类「只给一个人、一个问题做的材料」因为制作门槛下降第一次变得值得。**【原站核验】** 全文已读。 为什么值得你花时间这条同时解决两件事，而且两件都落在你的日常上。**第一件是沟通**：「对齐一下」是你工作里的高频动作，而文字落到每个人脑子里会变成不同的画面——一个能改数字的最小网页比十轮描述都省时间，而且它把讨论从「我觉得」「你觉得」变成「你说的提高，具体是改这里吗」。**第二件是产品**：这正是你画布节点在做的事（拖动、立刻看到结果），文章给的是把它用在「理解与被理解」而不是「生成」上的用法——**你完全可以把「生成一个可交互解释页」做成平台里的一个小能力**，因为你的用户也在做同一件对齐工作。文章里那段提示词可以原样抄走（把漏斗换成你的分镜时长表、参数面板、成本模型都行）。**今天可做**：把那段提示词存进你的常用提示词库，下次评审分镜、转化或任何多层关系时，先让它生成一个能改数字的网页再开口。 上手成本15 分钟（抄走那段提示词；自己做一个能改数字的网页约 20 分钟） 入口https://juejin.cn/post/7693358476032524298 读详情（翻译 + 要点）→
