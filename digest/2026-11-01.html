01 claude-mem：给编码 Agent 装一个跨会话记忆 给编码 Agent 加跨会话记忆。 中文 15 分钟 cn:juejin ›
是什么claude-mem 是一个给编码 Agent 用的持久记忆压缩系统：生命周期钩子自动记下工具调用和文件改动，模型把原始流水账压成语义摘要，再分别存进 SQLite（结构化事实）和 Chroma（向量检索）；本地 worker 暴露 4 个 MCP 工具做分层检索，Agent 先粗搜、再按需拉细节（渐进式披露）。作者 Alex Newman（thedotmack），Apache-2.0，当前 15.2.0，要求 Node ≥ 20，安装已覆盖 Claude Code、OpenCode、T3 Code、Antigravity CLI、Pi 和 DeepSeek Harness。 为什么值得你花时间你每天用编码 Agent，最固定的浪费就是新会话开头把项目背景再讲一遍；claude-mem 把这段重复压成一层可检索的记忆，而且明确支持 DeepSeek Harness。掘金文章引用 10-30 的 GitHub 快照：105,550 星、单日 +1,145，同赛道的 Hindsight 56,437 星。**今天就能做**：在一个只读仓库项目里用 `/plugin marketplace add thedotmack/claude-mem` + `/plugin install claude-mem` 安装（或 `npx claude-mem install`），重启宿主，新会话里问一个上一轮才聊过的细节，看它能不能给出带编号的引用。边界：`npm install -g` 只装 SDK，不注册钩子；托管观察器 30 天试用后回落到 Anthropic 套餐，不想登录就用 `--provider` 或 `CLAUDE_MEM_ONLINE_OPTIN=false`；压缩会丢原文措辞，后台记录要先划好 private 边界；星数是关注度，不是留存或效果。 上手成本15 分钟（插件安装 + 重启 + 一次引用验证） 入口https://github.com/thedotmack/claude-mem 读详情（翻译 + 要点）→

是什么Speridlabs 的 Idol 把一个物体的单张图片转成 3D Gaussian Splat：Gradio Space 跑在 ZeroGPU 上，输出 `.ply`，页面里可直接旋转查看；可调输入类型、10–100 步、guidance 0–10、time shift 1–6、Gaussian 数量和 seed。示例覆盖角色、食物、家具、Logo 和玩具，默认背包的 `.ply` 随 Space 提供；代码在 `speridlabs/idol-sdk`，权重在 `speridlabs/idol`，Space 是 Apache-2.0。 为什么值得你花时间你做画布 / 引擎接入，单图生成 3D 资产是最短的一条验证路径：先用一张产品图或角色图看几何和材质边界，再决定要不要把「图 → 3D」接进节点。**今天就能做**：打开 Space 选一个示例或上传自己的图，生成后看三件事——轮廓是否闭合、背面是否崩、放大后高斯是否糊成一片；满意再下载 `.ply` 去 Three.js / 引擎里加载。边界：输出是 Gaussian Splat，不是 mesh / USD，也没有 PBR；ZeroGPU 单次 120 秒，排队和输入质量决定结果；Space 的 Apache-2.0 不自动等于权重和 FLUX.2 / DINOv3 的商用条款，落地前逐项确认。 上手成本15 分钟（选示例生成一个 `.ply`；排队另算） 入口https://huggingface.co/spaces/speridlabs/idol 读详情（翻译 + 要点）→
04 Agent 架构怎么选：workflow 优先，多 Agent 只在两种场景值 四问决定 workflow 还是多 Agent。 中文 15 分钟 cn:juejin ›
是什么掘金作者郑恩赐把 Anthropic《Building Effective Agents》的选型原则拆成一套可执行判据：先分清固定形状的 workflow 和运行时形状的 agent；单 Agent 在「步骤 3–5 步、工具 3–5 个、无需并行」时是默认解；多 Agent 只有真并行和生成-校验双角色两类值得上。文里给了成本账：orchestrator-worker 比单 Agent 好约 90%，但烧约 15 倍 token；同等算力预算下多 Agent 只换来约 4% 提升、付出 4 倍成本；顺序链路按乘法衰减（单步 95% 可靠，5 步 77.4%，10 步 59.9%）。 为什么值得你花时间你在 wayfinder 这类 Agent 上做编排，最容易犯的错是「先上多 Agent 再说」；这篇文章给的是可复用的决策函数，而不是某个框架的广告。**今天就能做**：把文中的 `recommend_agent_architecture()` 抄进你的仓库，用五个参数跑一遍你手头的三个任务，先把「流程能固定却用了 agent」的那一个改回 workflow，量一下 token 和失败率。边界：90% / 15 倍 / 4% 这些数字来自 Anthropic 的公开研究，不是独立复现；框架对比是 2026 年的快照，AutoGen 已进维护模式；多 Agent 的收益高度依赖任务是否真并行。 上手成本15 分钟（读 + 抄 Python 判据 + 跑三个任务） 入口https://juejin.cn/post/7702483654677364774 读详情（翻译 + 要点）→
05 Arca：把 10 天级 Agent 任务的记忆和人工闸门拆开 把 10 天级 Agent 的记忆和人工闸门拆开。 跟人 1 小时 people:latent-space ›
是什么Latent Space 访谈 Arca 的 AI 负责人 Aman Singh：这家 AI 原生财富管理公司的 Agent 任务可以横跨 10 天，特点是 stop-start、多角色、多决策点、多交接；他们给每个客户建持久记忆，记录「发生了什么、下一步盯什么、谁负责哪个动作」，并自建 harness 按内部 benchmark 给任务挑模型。安全侧的做法很硬：交易和资金动作永远留在人手里，所有安全限制都是确定性的；Agent 在沙箱里写代码查数据，代码会被翻译成一套严格格式、原代码丢弃，再在格式上加闸后才到后端。 为什么值得你花时间你在 wayfinder 上跑长任务，最难的不是单步能力，而是「跨天不忘事、关键动作有人兜底」；Arca 把这两件事拆成了可抄的工程结构——按客户 / 项目持久记忆、自建 harness 保留换模型的自由、确定性闸门而不是用提示词求它别乱来。**今天就能做**：对照你现在的任务状态，先补两个字段——「这件事上次停在哪」和「下一步谁负责」；再把一个高风险动作从 Agent 工具列表里拿掉，改成人工确认。边界：这是一个公司的访谈，不是开放实现或 benchmark；10 天是任务跨度，不是单次运行时长；他们的 harness 和记忆系统没有开源，照抄的是结构不是代码。 上手成本1 小时（读访谈 + 对照任务状态改两个字段） 入口https://latent.space/p/arca/ 读详情（翻译 + 要点）→
