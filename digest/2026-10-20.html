是什么VAST 10-18 发布并开源的实时世界模型，核心是「世界状态与视觉渲染解耦」：交互系统维护输入、状态和规则，EdenLive 只负责按简化场景/参考视频、目标首帧和提示词持续生成精细画面。官方给的数字是 5B 模型在单张 RTX 5090、720P 下超过 24FPS，端到端延迟百毫秒级，能连续生成分钟级画面；代码、权重、技术报告和 Demo 都已开放。 为什么值得你花时间你做视频生成和画布工作流，最贵的一环是「改一处要重渲整段」；EdenLive 把「状态」和「画面」拆开后，交互系统只传状态变化，模型只做生成式渲染，这正是实时预览节点需要的那条分工。它还有两个直接可用的信号：一是 5B/单卡/24FPS 说明实时世界模型已经能在工作站上演示，不再是数据中心专属；二是它把「参考视频重渲染、换皮、具身数据增强」做成了同一模型的输入形态，素材二次利用的路径比纯文生视频宽。边界要写清：高频激烈交互、多角色同屏的身份保持、小物体精细控制、长时一致性都还没解决，现阶段更适合场景漫游/推箱子这类低频交互，别对外承诺「3A 游戏实时可玩」。 上手成本半天（下载权重 + 跑 Demo；只看技术报告 15 分钟） 入口https://github.com/VAST-AI-Research/EdenLive （项目页 https://vast-eden.ai/?p=edenlive） 读详情（翻译 + 要点）→

03 Harness²：不改模型权重，让 Agent 递归改写自己的 Harness 让 Agent 改提示词、记忆和工具来变强的框架。 中文 1 小时 cn:infoq ›
是什么Google Research 开源的递归 Agent 框架（Apache 2.0，支持 OpenCode 与 Codex，默认 OpenCode），定位研究项目而非官方支持产品。它把可修改的 Harness 拆成 8 类组件——系统提示词、护栏、记忆、工具指导、子智能体、Skills、脚本、插件——用「提出—探测—组合」在同一个任务上实际跑多套修改，再把有执行证据的经验存进跨任务的 Improvement Harness。 为什么值得你花时间你在 wayfinder 和雷达上做的其实一直是 Harness 工程：提示词、技能、子智能体、记忆怎么配，比换哪个模型更决定成败。Harness² 给了一个可抄的闭环：不要求任务有标准答案，用「不同 Harness 跑同一任务的行为差异」当证据；单步优化就能在权重不变的情况下把 WorkBuddy-Bench 提高 11.5 分、JobBench 提高 4.5 分、LAB 通过率提高 11.8 个百分点。代价是测试时计算成倍增加，而且 executor 默认不限网络、Codex executor 会关闭 sandbox——别拿生产仓库直接试，先在隔离环境跑一个自己的任务。 上手成本1 小时（读论文 + 跑一个 Benchmark；接自有任务另算） 入口https://github.com/google-research/harness2 （论文 https://arxiv.org/abs/2605.09998） 读详情（翻译 + 要点）→
04 Sphinx：push 前先答一道关于这段 diff 的题 推送前用一道题考你，确认你真的看懂 AI 代码。 小而美 15 分钟 hn:show ›
是什么给 agent-assisted development 用的 Git hook：push 受保护分支时，一个没看过你聊天记录的 reviewer 读 diff，问一个「这段代码在出错时会怎样」的问题；答错会解释原因并换场景追问，答对才放行。支持 Codex、Claude Code、Cursor、OpenCode、Pi 或纯 Git，可用现有 coding agent、OpenRouter 或任意 OpenAI-compatible endpoint，主打低 token；`npm install -g sphinx-understand` 后 `sphinx install` 即可，要求 Node 22.19+、macOS/Linux/WSL。 为什么值得你花时间你每天都在把 Agent 生成的代码推到 Gitea，真正危险的不是「代码有 bug」，而是「你已经看不懂它为什么这么写」。Sphinx 把「理解」变成 push 前的一道低成本关卡：答案不回传给 coding agent，`.env` 和密钥不会被打开，急的时候 `sphinx yolo` 放行且每次跳过都有记录。它测的是人不是 diff——能挡住「完全没看就推」，挡不住「看懂了但仍然错」，也可能被复制粘贴绕过；所以适合当可选的质量闸门，不要做成团队硬考核。 上手成本15 分钟 入口https://sphinx-six-theta.vercel.app/ （仓库 https://github.com/parthh01/sphinx） 读详情（翻译 + 要点）→
05 StartLux：给 Agent 输出选项概率的决策模型，27B 登顶 Decision Index 给 Agent 做路由和工具选择的开源决策模型。 中文 半天 cn:infoq ›
是什么StartLux 是一组专门做决策的模型：输入当前状态和候选选项，直接输出各选项概率，供 Agent 做任务路由、工具选择、权限判断。10-16 的 HF Decision Index 0.3.2 榜上，27B Instant 以 69.12 分在 174 个参评条目中排第一；Instant 覆盖 0.8B/2B/4B/9B/27B，单次前向出概率，AutoThink 覆盖 4B/9B/27B，先看初始置信度，低于阈值（默认 0.6）才生成推理再按 75/25 融合。 为什么值得你花时间当 Agent 开始频繁做「走哪条工具链、要不要请求权限」这类判断时，一个专门输出概率的小模型比让大模型写一段解释更便宜、更可测。StartLux 的实测数字很具体：H200 + vLLM 单并发下 Instant 中位延迟约 25–52ms；DecisionPivot 上 27B Instant 成对准确率 75.4%、AutoThink 86.9%；把阈值从 0.9 降到 0.6，综合分只掉 0.37，但条件敏感任务掉 19.7 个百分点——这说明阈值要按任务复杂度调，不能只看榜单。许可要先看清：推理代码 Apache 2.0，权重 CC BY-NC 4.0 仅限非商业，商业部署要另谈。 上手成本半天（起 vLLM 跑 27B；先读榜单与阈值实验 15 分钟） 入口https://github.com/StartLuxLabs/StartLux-Decision （模型合集 https://huggingface.co/collections/startlux-models/startlux-decision-v11-autothink） 读详情（翻译 + 要点）→
