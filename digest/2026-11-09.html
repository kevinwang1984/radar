02 agent-browser：给 Agent 一个带编号的浏览器 把网页读成带编号文本，让 Agent 点元素。 中文 15 分钟 cn:juejin ›
是什么Vercel Labs 的 Apache-2.0 浏览器自动化 CLI，Rust 写成（文章口径 46,578 星、3,192 fork、120 个 release）：核心是 `snapshot`——把页面读成紧凑的无障碍树，每个可交互元素带 `@e1` 这样的 ref，模型读文本、点编号，再 snapshot 确认结果。浏览器不退出：第一条命令拉起后台 daemon，daemon 通过 CDP 长连接控制浏览器，之后每条命令都是一次短 shell 调用；`--session` 隔离会话，无头模式一小时无命令自动保存退出。安装 `npm i -g agent-browser && agent-browser install`，七条命令跑通 open → snapshot -i → click @e1 → get url → close。 为什么值得你花时间你做 wayfinder / 浏览器自动化，最贵的不是点错一次，而是错误到流程末尾才爆：agent-browser 的 click 在被遮挡、隐藏、禁用、视口外时直接报错，而不是假装成功；ref 在导航 / DOM 变化后失效，逼你每步重新 snapshot，失败信号即时。它还自带 skills、MCP server、auth vault、domain allowlist、action policy、trace / profiler / vitals / react / a11y、多会话 dashboard，既能当裸 CLI 给 cron / CI 用，也能挂进 MCP 宿主——这套「文本页面 + 可寻址编号 + 诚实失败」正是浏览器侧最该先定下来的协议。**今天就能做**：装完跑 `agent-browser open example.com`、`snapshot -i`、`click @e1`，再拿你们画布 / 后台的一个真实页面跑一遍登录态（`--auto-connect` 接管本机 Chrome），重点看遮挡与 ref 失效的报错；把 snapshot-ref-act 循环接进一个现有脚本。边界：46k 星是文章口径；接管本机 Chrome 等于把登录态交给调用方，权限边界要自己划；无头会话一小时回收，长流程要配 session persistence。 上手成本15 分钟（装 + 七条命令跑通） 入口https://github.com/vercel-labs/agent-browser 读详情（翻译 + 要点）→
03 Pi：把编码 Agent 收回到「最小内核 + 扩展」 极简开源编码 Agent，系统提示更小。 方法 1 小时 hn:stories ›
是什么Pi 是 Earendil 的 MIT 开源编码 Agent（`curl -fsSL https://pi.dev/install.sh | sh`）：官网定位「a minimal agent harness」，默认不带 sub-agents、plan mode、权限弹窗、TODO、后台 bash，而是用 TypeScript 扩展、skills、prompt templates、packages 自己搭；支持 15+ provider、树状会话（`/tree` 回到任意分支、`/share` 导出）、AGENTS.md / SYSTEM.md、可替换的 compaction，以及 interactive / print / RPC / SDK 四种模式。Caleb 的迁移文（9 月 21 日发布、11 月 7 日更新，HN 675 分）列了他离开 Claude Code 的原因：AGENTS.md 支持来得太晚；同一时间只能一个会话连 IDE；官方 GUI 扩展缺一半 slash command、没有自定义状态栏；2026 年 244 个 release 里超过 3/4 改过 system prompt 或工具描述；默认 Bash 工具描述接近 3,000 token；以及 dynamic workflows、agent teams、ultrareviews 这类他用不上的功能膨胀。 为什么值得你花时间你在 Gitea 上跑 wayfinder，harness 的 system prompt 和工具描述就是你的「隐性代码」：它们一变，同一仓库的成功率和 token 账单就变，而且很难回归。Pi 给了一个反面参照——把内核压到最小，把 sub-agent、plan mode、权限门都做成可替换扩展；文章里「3/4 的 release 改了 system prompt / 工具描述」和「Bash 描述 3,000 token」这两个数字，正好可以拿去量你现在的 harness。**今天就能做**：装 Pi，拿一个真实仓库任务和现用 harness 各跑一遍，比 system prompt / 工具描述 token、首轮成功率、需要人工纠正的次数；再读它的 extensions 示例（subagent、plan-mode、permission-gate），看哪些该抄进 wayfinder。边界：Caleb 是单作者体验，不是基准；Pi 故意不内置很多东西，迁移要自己补；文章 9 月首发、11 月更新，Pi 已到 1.0，细节以官网为准。 上手成本1 小时（装 + 迁移一个仓库 + 对比一轮） 入口https://pi.dev/ 读详情（翻译 + 要点）→

是什么InfoQ 对腾讯云 WAND 团队及客户的采访：AI 短漫剧从分镜到成片，行业经验约 10 次生成才有 1 次满意；按单次 10 元算，一个可用镜头的生成费就是 100 元，可用率提到 50% 则降到 20 元，还没算人工筛选 / 修改。WAND 的三条降本路径：生成前用 3D 白模定空间 / 机位 / 运动，专业场景用混元等基座后训练的 WAND-Vega（Lite / Pro），生成后只对局部瑕疵做 WAND-EraseVibe+ 擦除修复，而不是整段重生成；官方称综合成本降约 20%。客户数据：漫森文化镜头可用率 30% → 50–80%（稳定约 80%），精品 AI 短剧单部 10–20 万元、成本再省约 30%、效率提升约 30%；紫讯科技图片有效使用率 50–60% → 70–80%；某平台 82% 的视频模型调用已由 Agent 发起。 为什么值得你花时间你做视频生成平台，真正该盯的指标不是「单次生成多少钱」，而是「一个可用镜头多少钱」：10 次里 9 次废片，单价再低也贵；反过来，白模 / 首尾帧 / 参考图把约束前置、局部修复替代重生成，可能比换更便宜的模型更有效。这篇文章还给了产品边界：Agent 可以接管大部分模型调用，但专业团队仍要在关键节点看中间结果、只改人物表情 / 镜头运动，所以「可编辑的中间态 + 人工审批」不能省。**今天就能做**：拿你现有的一条视频流水线，连续记 20 个镜头的「生成次数 / 可用次数 / 人工修改分钟」，算出可用率与单可用镜头成本；再用 WAND 的 API 文档或你现有的模型，给同一批镜头加一个前置约束（白模或首尾帧）和一个局部修复步骤，重测。边界：厂商采访，20% / 30% / 80% 都是腾讯云与客户自报，没有第三方基准；WAND 是闭源云产品；「10 次」是行业经验，不是普适常数。 上手成本15 分钟（读完 + 用文章的口径算一遍自己的账；API 另计） 入口https://cloud.tencent.com/document/product/1823/138195 读详情（翻译 + 要点）→
