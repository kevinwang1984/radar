是什么Apache-2.0 的开源 Agent 视频工作室，定位是 Claude Motion / CapCut 的开源替代。它用 HTML/CSS/JavaScript 描述场景、排版、转场和时间轴，Agent 拆完参考片后把镜头重建成可编辑项目，在 Studio 里改时间线、换素材，再从同一个项目渲 MP4；图片、视频、音乐、配音走 BYOK（Bring Your Own Keys，自带模型账号密钥）的模型网关。技能页显示 3.0K 安装、仓库 14.8K 星、5 天前首次收录，Snyk 审计 Fail；Agent 侧通过本地 stdio MCP（Model Context Protocol，让编程助手接外部工具的协议）接入，支持 22 个本地宿主，含 DeepSeek Harness。 为什么值得你花时间你的「一句话成片 / 画布节点」现在最缺的不是模型，而是「生成完之后还能改」的那一层：OpenMotion 把视频拆成可读的 HTML 场景 + Motion.md（镜头顺序、时间、转场的 Markdown 描述）+ 版本快照，等于给了一个能直接抄的项目结构，而且它已经能接进 DeepSeek Harness。今天先 clone 下来跑通 Studio，拿一条 30 秒参考片走一遍「拆解 → 重建 → 导出」，重点看两处：Motion.md 能不能表达你现有的分镜字段、修订检查能不能挡住并发改稿。边界：本地要 Node.js 且 `npm ci` + `build:studio` 不轻；发布到各平台和团队协作都还在路线图；Snyk Fail 要自己看权限。 上手成本1 小时（clone + npm ci + build:studio） 入口https://github.com/nexu-io/openmotion 读详情（翻译 + 要点）→

是什么Gemini API 11-19 放出的 Tool Retrieval 预览（Interactions API v1beta）：在 tools 里加 `{"type":"tool_search"}`，给长尾工具标 `"defer_loading": true`，模型初始只看到名称和简短描述，完整的参数 schema 留在上下文外；需要时先检索、再加载、再调用，三步都记在 interaction.steps 里。检索结果追加在对话后半段，所以系统提示和核心工具前缀不动，多轮对话的前缀缓存（prefix caching，把开头固定部分缓存下来省钱提速）还能命中。 为什么值得你花时间你的画布 Agent 一旦把节点操作、素材库、发布接口都挂成工具，就会撞上「工具越多越慢越贵」；这条给了一个不用自己搓向量索引的官方解法，而且点出了自建检索最常见的坑——每轮改 Prompt 开头的工具列表会让前缀缓存全失效。今天先数一遍你 Agent 的工具数：超过二三十个、且长尾工具多数轮次用不到，就值得拿一组真实对话测词元账单和调用准确率。边界：只支持较新的 Interactions API；一次请求只能有一个 tool_search，漏写会直接 400；工具太少或每次全用时不划算。 上手成本15 分钟（已有 Gemini API key） 入口https://juejin.cn/post/7710701905597186063 读详情（翻译 + 要点）→
