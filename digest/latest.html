是什么Hugging Face 工程师用一个月 AWS Trainium3（trn3.48xlarge，64 个 NeuronCore——AWS 自研 AI 芯片的计算核心）把 Lightricks 的 LTX-2.5 视频模型跑起来：模型加载后，半台机器（32 个 NeuronCore）生成 10 秒 2048×1024 带声片段约 22–23 秒，和 LTX 官方 API 的 10 秒 1080p 23.7 秒基本打平；第一次跑 960×544 要 5 分 20 秒，五天优化到 14 倍。更值得抄的是「电影文件」：一个 JSON（结构化文本格式）数组，每个镜头有 name / prompt / seed（随机种子，用来复现同一版抽卡结果），用 `from`（从上一镜最后几帧开始）和 `to`（结束在下一镜前几帧）把镜头串起来，保证角色和场景跨镜不漂；生成之外只有约 160 行 Python 负责排序、裁帧、拼接，代码已开源。 为什么值得你花时间你做视频生成、自动分镜、一句话成片，最缺的往往不是单镜画质，而是「多镜之间怎么接」的数据结构。这套 from / to 帧链正好可以映射成画布上的镜头节点：主镜先出，前后镜头各自吸附主镜的首尾帧，重跑时用 seed 复现同一条；演示里海豹从冰面到落水的四个镜头就是这么接的。另一个信号是硬件：非 NVIDIA 路径已经能跑到 API 同级速度，选型时不必默认 CUDA（NVIDIA 的 GPU 计算平台）一条路。今天可以只做一件事：把你现有的一条三镜分镜改写成这个 JSON 结构，看你的生成链路能不能吃下「首尾帧 + seed」这两个约束。边界：这是一个人五天的实验，不是产品；跑通要 AWS Trainium3 实例；单镜上限 20 秒，声音不跨镜延续，细节仍要每镜抽 4 次挑 1 条；模型加载约 3 分钟。 上手成本半天（读镜头链代码；跑通需 AWS Trainium3） 入口https://github.com/dacorvo/video-generation 读详情（翻译 + 要点）→

是什么JioHotstar 工程团队拿六种「让编码智能体看懂大仓库」的方案做对比：文件系统工具（本地检出 + 搜索 / 读文件）、Sourcebot、Graphify、CocoIndex Code、Repowise，以及自建 RAG（检索增强生成，先从库里找片段再喂给模型）管线。评测用 SWE-bench 与 CodeScaleBench 的部分数据集，再加一套自家代码库的问答，解题模型是 Claude Sonnet，指标是准确率、词元（token，模型读写文本的基本单位）消耗、交互轮数和工具易用性。结论不是「谁最强」，而是「按任务配」：目标明确的任务，文件搜索基线依然能打；难题上 Sourcebot 比基线更准也更便宜；需求模糊、跨多模块时才轮到语义检索；加检索层不必然提准确率，也不必然省词元。 为什么值得你花时间你正在给 wayfinder 这类编码智能体喂仓库上下文，最容易踩的坑就是「先上向量库再说」。这条给了可操作的判断：先用文件搜索 + 符号查询打底，只在「说不清在哪、跨多个模块」的任务上加语义索引；同时把工具调用轨迹也当成指标，看检索有没有减少瞎逛。今天可以拿你最近三个真实任务分类：定位明确的、跨模块的、需求模糊的各一个，分别用「纯文件搜索」和「加检索」各跑一次，比词元和轮数，而不是只比答没答对。边界：只用了一个模型（Claude Sonnet）、部分数据集，文中也没有多次运行的数据，原文评论里就有人追问方差；它是工程博客，不是同行评审；别把结论直接套到所有模型。 上手成本1 小时（读结论 + 拿自己仓库试） 入口https://www.infoq.cn/article/Ql4GGMIEqA3bI2W2lh7h 读详情（翻译 + 要点）→

是什么DoorDash 的对话式购物助手 Ask DoorDash 里，生鲜杂货复购原来每次请求都要重建一遍购物清单，端到端约 16 秒。改法是「预计算」：离线读 90 天购买历史与用户画像，用批量 LLM（大语言模型）推断哪些是周期性商品，再用确定性规则校验，把可复用的清单存下来；服务路径只做检索，并按当前目录做三级降级匹配（原店商品 → 目录商品 ID → 搜索词），缺货、换包装也不至于整单重算。结果延迟降到约 2 秒，购物清单查看量翻倍，该流程下单率提升约 34%；简单改动（改数量、删商品）直接改结构化清单，不再过一次 LLM。 为什么值得你花时间你的 AIGC 平台也在跑「用户一句话 → 分镜 / 素材 / 渲染」的长链路，很多步骤其实可以提前算：风格预设、常用镜头模板、素材检索、历史项目上下文，都不必每轮重新推理。这条给的判据很直接：哪些必须留在智能体循环里，哪些可以离线预计算，哪些用确定性代码兜底；共享智能体平台把编排、记忆、追踪、评测和发布控制抽出来后，新增一个领域智能体从「十倍时间」降到一周。今天可以画一张你自己的链路图，把每个节点标成「实时推理 / 预计算 / 确定性代码」，先挑一个最贵的实时节点挪出去。边界：这是 DoorDash 自报的案例，不是可复现基准；生鲜复购和内容生成的任务结构不同，预计算的前提是需求可预测；别把「加缓存」当成万能药。 上手成本15 分钟（读案例，画自己的链路） 入口https://www.infoq.cn/article/2uDBVKjk3kJXRb6CqQfu 读详情（翻译 + 要点）→
