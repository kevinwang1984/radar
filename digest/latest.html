是什么HeyGen 开源的 HyperFrames 命令行工具，项目本身就是 HTML 视频合成：`npx hyperframes init` 用 9 个模板起项目，`lint` 查结构，`check` 开浏览器查运行时、排版溢出、遮挡、对比度、音频与运动断言，`preview` 热重载，`render` 出 MP4 / MOV / WebM / GIF / PNG 序列 / HLS，支持 draft / looks / delivery 三档画质；还能 `capture` 抓网页、`transcribe` / `tts`、`reverse` 量原片再重建、`diff` 用 SSIM 对片。需要 Node.js 22+ 与 FFmpeg。 为什么值得你花时间你的视频管线现在多半是「调模型出片 → 人工看」，它把「合成、检查、渲染」变成可脚本化的本地工程：同一套 HTML 时间线可以在 CI 里 lint/check，渲染前就能抓到文字溢出、字幕遮挡、首帧空白、静音片；`reverse`/`diff` 还能把一条参考片拆成镜头和运动曲线，给你自己的分镜节点做回归。今天可以拿一条 15 秒产品片，按 init → check → draft render 跑一遍，看它能不能替你省掉一轮人工 QA。边界：Snyk 审计是 Fail（Socket / Agent Trust Hub 是 Pass）；CLI 默认带使用信标与更新检查，可用 `HYPERFRAMES_NO_TELEMETRY` / `HYPERFRAMES_NO_UPDATE_CHECK` 关；云渲染与部分 Pro 模板走 HeyGen 付费能力。 上手成本1 小时（Node 22 + FFmpeg + 跑一遍 lint/check） 入口https://www.skills.sh/heygen-com/hyperframes/hyperframes-cli 读详情（翻译 + 要点）→
02 learn-taste：把用户的每次纠正写成 Agent 的规则 把用户的每次纠正写成 Agent 能读的规则。 其他 15 分钟 weekly:skills-sitemap-diff ›
是什么Emil Kowalski 新放出的 skill（skills.sh 上 8.3K installs、仓库 57.2K stars）：它只做一件事——从当前（以及可读的）会话里收集用户对 UI 的纠正，把每条纠正变成一个带原因的规则，写进下一个 Agent 会读的地方；它不改组件代码，也不添加用户没表达过的规则。工作流是先收集纠正，再逐条提议、等用户确认，最后优先落成 lint / token 限制 / 测试，而不是一句容易被上下文挤掉的散文。 为什么值得你花时间你做画布和设置页，最贵的不是写第一版，而是同一个审美错误被不同 Agent 反复犯；这条把「用户改了什么、为什么改」沉淀成可执行规则，今天就能拿最近一次 UI 返工跑一遍，看它能不能把「按钮圆角、间距、错误态保留」这类纠正变成一条 lint 或一条 token 约束。边界：只认用户自己的口味，不能拿通用最佳实践硬塞；用户没给原因时它只能标 inferred 并等你确认；它写规则不写代码，规则写错会在之后每个会话重复。 上手成本15 分钟（装 skill + 跑一次纠正会话） 入口https://www.skills.sh/emilkowalski/skills/learn-taste 读详情（翻译 + 要点）→
