03 Jev（TypeSafe System One Models） 只做判断、不写文字的分类路由模型，成本极低。 跟人 需要申请 key people:latent-space ›
是什么TypeSafe 9 月 15 日发布的 System One 模型 Jev，创始人 Diogo Almeida 是 ChatGPT 共同作者，两年 stealth 做出的新训练方式叫 RLCD（calibrated decisions）。它不做自回归文本生成，而是「给状态 + 类型化问题，直接返回结构化答案」：三种原语 Choice（从列表选）、Score（按 rubric 打分）、Noul（命题真假 0–1），一次 API 调用可以混着问多个问题、并行独立求值，返回带概率分布和置信度，**从结构上就不存在解析失败和工具调用参数错误**（官方对比图里 Jev 工具调用错误率 0%）。价格每百万输入 token $0.042、输出按「低到不可测」计；官方口径同等任务质量对标 GPT-5.6 Terra 而成本约 1/100，推文口径是快 20–200 倍、便宜 40–400 倍。代价是它不能生成自由文本。目前是 early access 申请制，文档和 quick start 已公开。 为什么值得你花时间你的 agent 链路里有一大堆「不值得让前沿大模型写一段话」的判断——意图分类、工具路由、结果打分、质检门、是否重试。把这些从「先生成再解析」换成 typed 返回值，是省钱也是减少一类长尾故障；这两天就能拿 early access 文档里的 Choice / Score / Noul 和现有 prompt 逐条对照，周末试着把最贵的一条判断换掉。 上手成本需要申请 key（early access） 入口https://www.latent.space/p/ainews-jev-a-system-one-model-that 读详情（翻译 + 要点）→

06 多智能体分解的产出守恒律 用生产日志算出每加一层子代理只拿回一半。 中文 15 分钟 cn:juejin ›
是什么掘金 9 月 16 日对论文《Decomposition Buys Integrity, Not Yield》（Rong He，arXiv:2609.17464，9 月 15 日提交，附完整实验代码）的中文拆解。核心模型：agent 拿到 b 个条目时保留任一条的概率是 r(b)=C·b^(−δ)，于是深度 k 的树最终产出是 **C^k·N^(1−δ)**——任务规模和架构是分离的两项，架构只能贡献每层 C≤1 的衰减，而 δ 这个指数谁都躲不掉。实测取自 600 条生产 deep-research 轨迹：δ=0.34 [0.30,0.38]；在「工具给定条目边界」的 hop 上直接观测（不是外推）到 C=0.571、共 16,082 个 hop；另有 1,012 条标注轨迹显示每 16 份子 agent brief 就有 1 份跑偏，μ=0.939，于是每层实际代价 C·μ=0.536，两层只剩 0.287、三层 0.154。文章还给了三条反直觉结论：分层买的是「根节点上下文」（N → N^(1/k)，它是唯一无法廉价遗忘的状态）、等花费下两层要到 N=403 个发现才胜过扁平、以及**委托是开局决策而不是上下文快满时的应急**（743,819 次生产工具调用的 hazard 模型显示上下文翻倍反而让委托概率略降，odds ratio 0.969）。 为什么值得你花时间你正在搭的 agent 编排迟早要回答「要不要再拆一层」，这篇给的是可以直接写进设计文档的系数和决策树（N<50 别分层、50–400 看根节点、>400 分 2–3 层），还附了「先测自己的 δ 和 C」的测量方法；15 分钟读完，能立刻给现有链路加一条「子 agent 找到的发现有多少活到了最终输出」的监控。 上手成本15 分钟 入口https://juejin.cn/post/7686040694946791433 读详情（翻译 + 要点）→
07 基于「行为评估」准则评估智能体 把 agent 测试从看结果改成断言它的每一步动作。 中文 15 分钟 cn:juejin ›
是什么掘金 9 月 16 日文章，解读 Google 9 月 9 日 Harness Engineering 文章提出的 Behavioral Evaluation。问题场景很具体：模型没变、业务没变，只改了 System Prompt、Tool Schema 或加了个工具，跑 benchmark 成功率反而降了，而端到端分数只告诉你「变差了」，不告诉你「哪一步坏了」。做法是把 agent 当软件测：除了 `assert response == expected`，还要 `assert agent.called_tool("test_runner")`——改完 Build 文件有没有跑 validator、写完代码有没有调测试、引用的是不是正确的仓库、信息不全时是追问还是瞎猜。文章用电商售后「帮我退掉耳机」举例：只看结果是 PASS（「已提交退款申请」），打开 trace 才发现它查错了订单、没确认发货状态。 为什么值得你花时间你的 agent 要跑几十轮长流程，这类「答对了但过程错了」的失败在线上比答错更难查；这篇文章把「哪些行为该被断言」列成了清单，可以照着给你现有链路补 3–5 条行为回归断言——以后改 prompt 或换模型时，回归跑一遍就知道改坏了什么，而不是等业务方报障。 上手成本15 分钟 入口https://juejin.cn/post/7686010356546011199 读详情（翻译 + 要点）→

是什么Google DeepMind 9 月 1 日发布，覆盖 Gemini 3.7 Flash / 3.6 Flash / 3.5 Flash-Lite。原来的做法是「静态」抽帧：按固定帧率（默认 1 FPS）把整段视频喂给模型，长视频要么烧 token 要么丢细节；换成 agentic 之后，模型带着目标在视频里主动搜索、回看、放大——内部工具按需加载相关片段，自行决定看哪一段、用几倍帧率、看画面还是听音轨还是读转写。官方数字：token 消耗最多降 88%、分析成本最多降 66%、准确率最多提 7%，其中 3.7 Flash 落在准确率-成本帕累托前沿。能力清单直指以前做不了的事：**亚秒级片段定位**（1 FPS 必漏的切点，可做精确自动剪辑）、多小时视频里的 needle-in-a-haystack、对可疑时间窗临时提高帧率做异常检测、精确计数。开启方式只是把 API 配置里的 processing 设成 `"agentic"`，按标准 token 计费、无额外功能费；Google AI Studio 与 Gemini Enterprise Agent Platform 都能用，未来说要驱动 YouTube 的 Ask YouTube。 为什么值得你花时间你在做自动分镜、镜头筛选和成片质检，这套能力正好是「先理解素材再剪辑」那一环，而且不是新模型而是现成模型加一个参数：下周一就能把一条长素材丢给它，试切点定位与镜头计数，顺手把长视频理解的成本压下来——这件事 5 分钟就能改，省下的是你整条素材处理链路的 token 账。 上手成本15 分钟（Gemini API key） 入口https://deepmind.google/blog/introducing-agentic-video-in-gemini/ 读详情（翻译 + 要点）→
