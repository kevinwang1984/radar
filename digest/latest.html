01 Colibrì：把 744B MoE 的专家放进 SSD，笔记本也能跑 把大模型权重按需从 SSD 读入的推理引擎。 中文 15 分钟 cn:qbitai ›
是什么一个 2026-09-26 在 GitHub 上冲起来的开源推理引擎（量子位 09-26 报道时约 32k Star，Apache-2.0，作者 JustVugg，仓库 `JustVugg/colibri`）。它把 VRAM / RAM / NVMe 当成同一套分层内存：GLM-5.2 共 744B 参数、每 token 只激活约 40B，其中 Attention、Embedding、共享专家等 Dense 部分约 17B，int4 后约 9.9GB 常驻内存；19456 个路由专家（约 370GB）全部留在磁盘，由 Router 选中的才现场读入，配每层 LRU、按调用热度学习的 pinned 热存，以及「提前一层预测下一层专家」（作者实测相邻层路由相关性可预测率 **71.6%**）来重叠计算与 I/O。已支持 9 个模型家族，从 OLMoE 7B 到 GLM-5.2/5.3（744B）、Inkling（975B）、Kimi K3（2.8T）；官方硬件表写明 **GPU 非必需**，GLM-5.2 磁盘约 372GB、RAM 16GB 起（24GB 舒适），Kimi K3 约 1.6TB 磁盘 + 32GB 内存起。速度实测：25GB 开发机冷缓存 0.05–0.1 token/s，128GB 纯 CPU 桌面约 1.8 token/s，6×RTX 5090 全常驻 5.8–6.8 token/s；双 NVMe 条带实测解码 +37.5%。发布页给 Linux / macOS / Windows 预编译包，`coli chat` 即可对话，另有 Web Dashboard 实时显示每个专家住在 VRAM / RAM / 磁盘哪一层，以及把 19456 个专家可视化的 Brain 页面。 为什么值得你花时间如果你的平台要自建推理或做私有化部署，这条给的是**可执行的显存档位表**：多大磁盘、多少内存、大致多少 token/s，还附带一条设计原则——专家放在哪一层只影响速度，不改变路由与精度（是语义等价，不是偷偷降质）。它也重新划了一次成本线：前沿开源权重不是非要 A100/机房，一台有 NVMe 的 32GB 机器就能跑，预算评估与 POC 的起点因此可以低很多。15 分钟能读完它的分层设计并对着自己的机器算一遍账。 上手成本15 分钟（读设计表与档位；真要跑另算，需 372GB 以上磁盘 + 16GB 内存起） 入口https://github.com/JustVugg/colibri 读详情（翻译 + 要点）→
02 Reladraw：用文字说清「谁放在谁旁边」 不写坐标的图表语言，只描述谁挨着谁、谁在谁上方。 小而美 15 分钟 hn:show ›
是什么一个 v0.5.0 的 TypeScript 图表语言（Apache-2.0，仓库 `reladraw/reladraw`），今天在 HN 拿到 139 分。它站在两个极端中间：Mermaid / Graphviz / D2 这类自动排版语言能声明实体与连线，但你**说不出东西该放哪儿**；draw.io / Excalidraw / Figma 能精确摆放，但每次改动都是手工活，而且 agent 得先从坐标里把画面反推出来才知道该改哪个数。reladraw 的做法是让文件里**一个坐标都没有**：`node store "Database" right of app level with app`、`between cluster.desktop1 and cluster.laptop1`，距离全是相对的；求解器按最长路径解一组最小距离约束，得到唯一的最紧凑排布，间距是**下限**而不是精确值——往两个东西中间插一个新节点，它们会自动让开，删掉又合拢。非重叠也由这套推导出来，不必逐对声明；溢出、越界、箭头穿节点这类只能从几何里算出来的问题，留给「诊断报告」输出（尚未实现）。仓库自带 agent skill（这门语言太新，任何模型的训练数据里都没有），装法是 `npx skills add reladraw/reladraw -g`。 为什么值得你花时间你在做画布 / 节点类工作流，这条正好补上「自动排版」与「手摆坐标」之间缺的那一层——**意图是文件里的一句陈述，改图就是改那句话**。更值得抄的是它的 agent 视角：Agent 能重读自己的文本确认「数据库在 API 下面」，却没法确认「两个簇重叠了」，所以它把「可陈述的意图」与「可从几何算出的诊断」明确拆成两件事，这个划分可以直接搬到你的画布数据模型上。15 分钟能在浏览器里跑通一个例子。 上手成本15 分钟 入口https://github.com/reladraw/reladraw 读详情（翻译 + 要点）→
