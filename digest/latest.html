05 一位首席架构师的 5 条反常识：先搭骨架、主 Agent 不准写代码 一位首席架构师用 Agent 写代码的五条反常识规矩。 中文 15 分钟 cn:infoq ›
是什么首席架构师 Carlos Kelkboom 在播客里给出的五条：① 自己先搭代码骨架（目录、关键文件、类名 / 函数签名），再让 Agent 填；② 主 Agent 不准改代码和文件，只负责对话、检索和确认意图，理解把握超过 90% 才建议启动执行 Agent；③ 生成的代码如果一眼认不出自己预期的结构，就扔掉重来，执行放在独立 Git Worktree 里；④ 尽量让 Agent 一次完成较大任务，因为它在已有代码上反复改的能力明显更差；⑤ 并行开多个 Agent 探索不同方案，再让一个 Agent 比较、只合并好的部分。 为什么值得你花时间这五条正好戳中「Agent 越写越快、项目越改越乱」的那个点：同一个列表功能在一个月里被重复实现五次、部署脚本被悄悄换掉、PR 下没人讨论——这些不是模型能力问题，是骨架和边界没定。最值得抄的是「主 Agent 不碰代码」和「看不懂就扔」：前者强迫先把意图问清楚，后者用 Git Worktree 把试错成本压到一次丢弃，而不是在错误结构上继续打补丁。代价是前期要花 20–60 分钟搭骨架，而且要求你自己有架构判断；对不熟悉的语言，他建议先让 Agent 对比成熟开源项目、讲清取舍，再自己写骨架。 上手成本15 分钟（读完）；落地一周 入口https://www.infoq.cn/article/tgqMEJsqXfX6YzAcOiAR （播客 https://www.youtube.com/watch?v=mkN4uRZYPfs） 读详情（翻译 + 要点）→
