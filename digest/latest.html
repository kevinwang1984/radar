是什么Cloudflare 2026-10-09 为 Workers 和 Durable Objects 上线的按需剖析：针对已部署、正在接流量的隔离实例采样，而不是新起一个实例；在 Workers Observability 的 Flamegraph 页面或 `cf` CLI 发起，CPU 以 1ms 间隔采样，结果渲染成可点击的交互式火焰图，也能下载 `.pprof` 用 pprof 分析；Durable Objects 可按对象名指定实例。 为什么值得你花时间你做 Web / API，最难受的性能 bug 是「线上慢、本地复现不了」；这个功能直接抓生产环境里那个正在跑的 isolate，火焰图越宽的函数就是越吃 CPU / 内存的那段，Cloudflare 自己用它在 R2 的 JSON replacer 上找到重复递归、把函数提速 2.7 倍，又靠堆剖析发现「已禁用」的 Prometheus 代码仍在分配内存、把 P999 从 133MB 降到 118MB。**今天就能做**：如果 Workers 承载了你的 API / 边缘逻辑，先开 source map，再去 Observability → Flamegraph 抓 10 秒 CPU profile（或 `cf workers versions profile latest --worker-id ... --duration-ms 5000 --profile-type cpu > worker-cpu.pprof`），按最宽的函数逐个看；把「线上抓 profile」加进你的排障顺序，排在「本地复现」之前。边界：只支持 Workers / Durable Objects；目标版本必须有足够流量；按需剖析不是持续监控，短窗口可能漏间歇问题；内存剖析只反映采样窗口内的分配，不是完整留存；TypeScript 不开 source map 会看到混淆名。 上手成本15 分钟（开 source map + 抓一次 CPU profile） 入口https://developers.cloudflare.com/workers/observability/profiling-in-production/ 读详情（翻译 + 要点）→
