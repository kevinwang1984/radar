02 用 Archon 把 Issue 到 PR 做成可停止、可接管的四段流水线 把 Issue 到 PR 拆成可验证、可预算停止的四段流水线。 中文 1 小时 cn:juejin ›
是什么掘金 10-18 的实践文（作者 Shockang），以 Archon 的 YAML 工作流与工作树隔离为基础，把自动编码拆成 Triage / Fix / Validate / Regression 四段：Triage 五个节点——读候选 Issue、读项目规则、查现有 PR/运行记录并用持久化租约领取、模型只输出受限 JSON 决策（number / action / reason）、校验后执行允许动作；Validate 用独立工作树与独立上下文，不继承实现者的自证结论，检查原始失败能否复现、边界输入是否仍正确、是否为了过测试而放松条件；预算在启动前预留，每次调用设输出/时间上限，达到阈值停止新任务；连续两次失败升级人工，失败次数按同一任务累计；回归失败先保存固定版本、输入与错误证据，再按指纹去重建单。文章反复强调：标签只展示状态，不是原子锁；`reason` 不能拼成 Shell；权限要分规则、工具权限、系统隔离三层。 为什么值得你花时间你手上的 wayfinder 和雷达都在跑「Agent 交付」，最缺的不是更强的模型，而是「失败可解释、可停止、可接管」的形状。这篇把每个失败去向写进状态流转：范围外 → 补充/拒绝/人工，测试失败 → 有限修复或接管，验证失败 → 退回修复，回归失败 → 去重建单；并且明确「独立验证隔离的是实现者的自证结论，不是 Diff」。可以直接抄的三条：Triage 的结构化决策 + 白名单校验、预算停止条件先于新请求、标签不是锁。边界：这是设计稿/实践文，不是 Archon 官方功能清单；文中示例阈值（每批 10 个、连续 2 次失败）要按自己仓库改，别照抄。 上手成本1 小时（读流程 15 分钟；接一条受控 Issue 约 1 小时） 入口https://github.com/coleam00/Archon （实践文 https://juejin.cn/post/7697558686809964579） 读详情（翻译 + 要点）→
