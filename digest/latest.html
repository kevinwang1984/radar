是什么`weave-os/router`，Apache-2.0、Go 写的**模型路由器**，插进任意编码 Agent（Claude Code、Codex、OpenCode、pi、Cursor）之后，在一次会话里**逐个 action 切换模型**——难的重构丢给前沿模型，简单的前端改动丢给便宜模型。官方页面的口径是 **Astra 级质量、2.3 倍更快、51% 的成本**（相比 GPT-6 Astra），论文依据是 Avengers-Pro（arXiv:2508.12631）。作者在 HN 上讲的三处改进里，**最关键的一处是「用 HMM 追踪 session state + classifier 分桶」**（自称最大的性能解锁），另外两处是用前沿 LLM 标注更大更杂的训练集、以及更准确地计算 cache eviction 的影响（**省钱主要来自这里**）。公开基准是配对比较（同一 harness、同一天、同题各跑两次）：**两组共 66 道与 124 道的 pass@2 都是 62.1%，对照 Astra 分别是 60.6% 与 66.1%——一组多解出 1 道，一组少解出 5 道，总体「打平」而不是碾压**；对照的 OpenRouter Auto 是 25.0% 与 54.0%。成本与耗时约为 Astra 的 52% / 54%，快 2.2–2.5 倍。接入是 `npx @weave-os/router --claude|--codex|--opencode|--pi`（Node ≥18），默认 BYOK，自托管要 Postgres 与一个可选的 HMM sidecar；`--scope project` 会把配置写进仓库。**要扣掉的分**：① **仓库我今天打不开**（`github.com` DNS 不可达），仓库元数据与 README 细节来自第三方镜像，**不是原站核验**——但 `weaveos.com` 本身可达，上面的基准页与价格页是我自己打开的；② 官方页面上图表标题与基准名的对应关系在抓取时**错位**，所以「哪组数字属于 Terminal-Bench 4.0、哪组属于 SWE-Atlas」请以页面为准，我只保留「一组略胜、一组略负」这个结论；③ 两个镜像的 HN 分数不一致（119 分 / 30 评论 与 109 分 / 37 评论）；④ 权重不开源、暂不支持本地 / LAN 上的模型，省钱的前提是你本来就在为前沿模型按量付费。 为什么值得你花时间**「每一步都用一个前沿模型」是你现在正在付的一笔糊涂账**，而这条给的是一个可量化的替代：一半的钱、质量打平、更快。三个可直接用的点：① **先量再换**——你不需要装它，也能立刻做它论文里那件事：把最近一次长任务的每一步按「这一步真的需要前沿模型吗」标一遍，量出可降级的比例；② **`--scope project` 把路由策略写进仓库的 settings.json**——也就是说路由可以**跟着仓库走**，这条对你 Gitea 上那种「一个仓库一套 Agent 配置」的用法是现成的形状；③ **它给的是配对基准而不是单边跑分**（同一天、同一 harness、同题各跑两次，还开了 `bench` 目录让人复现）——**这正是你评估任何「平替前沿模型」说法时该要求的证据形态**，比官宣分数可信得多。**今天可做**：打开它的 benchmark 页（可直连）看那三张配对图，再决定要不要在某个仓库上用 `--scope project` 试一周。 上手成本15 分钟（一条 `npx` 命令接入，但要自备上游 provider key；自托管全栈约 1 小时） 入口https://weaveos.com/products/router 读详情（翻译 + 要点）→

是什么掘金上的一篇方法论 + 实战长文（作者 hsfxuebao，20 分钟），把 2026 年这一波概念串成一条线：**Prompt Engineering（2022–2024）→ Context Engineering（2025）→ Harness Engineering（2026 初）→ Loop Engineering（2026 中）**。立论的两句引文是 Claude Code 的 Boris Cherny「我的工作变成了写循环」与 OpenClaw 的 Peter Steinberger「你不该再给 Agent 写提示词，应该设计循环」。它把 Loop 拆成三个核心：**明确可验证的目标与停止条件 + 反馈闭环 + 状态记忆**，再给出五个模块：**自动调度**（Claude Code 的 `/loop`，例 `5m` 一次检查部署状态；Codex 桌面 App 的 Automations；Cursor 没有原生命令，靠提示词 + 根目录 `PROGRESS.md`）、**工作隔离**（用 Git worktree，Claude Code 有 `--worktree`）、**技能沉淀**（写进 `SKILL.md`）、**工具连接**（MCP）、**子代理互审**，并强调状态记忆是贯穿这五个模块的那条线。文中两个案例：一个国际化任务约 15 分钟自主完成，一个「Electron + Python 服务端 + Web 管理后台」的桌面 App 近 50 分钟自主完成；也给了成本量级——**1 分钟一次的循环跑满 24 小时就是 1440 次调用**，以及「跑了 47 轮的状态机」这种真实回合数，还有从 Ralph Wiggum Loop 实践里来的「过度烘焙（Overbaking）」这个说法。**要扣掉的分**：① **`/goal`、`/loop` 这些具体命令我没能独立核验**（`claude.dev` 今天可达，但我没在官方文档里逐条确认），请当成「文中称」；② 文章配套的免费教程（`ai.codefather.cn/vibe`）**没有独立仓库**；③ 我抓到的正文尾部有少量截断。 为什么值得你花时间你在 `/implement` 里做的事——先对齐方案、再动手、收尾跑复查、再换标签——**本质上已经是一个循环，只是它靠你在外面驱动**。这篇的价值是给出**把驱动权交出去的四个必要件**：可验证的停止条件、反馈闭环、状态记忆、以及一个不污染主工作区的地方。三个可以立刻对照的点：① **「停止条件必须可验证」**——「代码更好看」不是停止条件，「测试全绿」才是；你可以在 `/implement` 的验收口径里逐个检查每一轮的目标是不是这种形状。② **状态写进文件（`PROGRESS.md` / `TASKS.md`）而不是留在对话里**——今天正文 06 的官方指南讲了同一件事（上下文会被压缩，文件不会），**两条独立来源指向同一个动作，说明这是当前这一代工具的硬约束而不是偏好**。③ **1440 次调用这个数字是个提醒**：循环的成本不在单次调用，在频率 × 时长——**开 `/loop` 之前先想清楚它要跑多久、什么时候必须自己停**。**今天可做**：读它的五模块清单，对着你现在的 `/implement` 流程标一遍「哪几个模块已经有人做、哪几个还靠我手动」。 上手成本15 分钟（读概念与五模块；真跑起来需要 Claude Code 或 Codex 订阅） 入口https://juejin.cn/post/7692336657548279842 读详情（翻译 + 要点）→
