02 tamserve：一份模型同时盯住 64 路摄像头 一份模型同时盯住多路摄像头。 小而美 1 小时 hn:show ›
是什么tamserve 是 SAM 2 / EdgeTAM 的「服务层」：原本的代码一次只能处理一段录好的视频，多路摄像头就要多份模型；tamserve 把每路的最新帧合成一次前向，返回每个目标的像素级掩码（mask，逐像素标出物体轮廓）。`pip install tamserve` 即用，8 路摄像头 2.2GB 显存（原方案 8.6GB），64 路 5.7GB、321 帧/秒（原方案约 70GB），DAVIS 2017 精度 0.8685 对 0.8686；还能用词（比如 “dog”）交给 SAM 3 自动找，或用 `PeopleTracker` 跟人。 为什么值得你花时间视频生成和后期里，跟踪是换背景、局部重绘、自动裁切、人物一致性的前置步骤；tamserve 把这块成本压到「可以常驻」，64 路 5.7GB 意味着能按每条素材流开跟踪而不排 GPU 队。今天在一张 4090 或 Colab 上装好，用一段自己的素材试「框一下、中途换目标、再纠错」，看掩码边缘和漂移。边界：只向前跟踪，不能倒放；纠错要重新框、旧轨迹丢弃；按词跟踪要另装 Meta SAM 3（3.5GB、需在 Hugging Face 接受许可、非 Apache-2.0）；`compile=True` 首次约 20 分钟。 上手成本1 小时（NVIDIA GPU + pip 安装 + 跑一段自己的视频） 入口https://github.com/aryamandarda/tamserve 读详情（翻译 + 要点）→

05 Codex sandbox：不搬容器，用系统沙箱约束每条命令 把 AI 编程助手的命令关进系统沙箱。 模型 15 分钟 vendor:openai ›
是什么OpenAI 11-18 公开 Codex 沙箱的设计：它不把 Agent 搬进 Docker，而是用各平台自己的隔离设施约束「在你现有环境里跑的命令」——macOS 用 Seatbelt（`sandbox-exec`）、Linux 用 bubblewrap + seccomp-bpf、Windows 用微软 MXC 做进程隔离；统一 API `spawn_command_under_sandbox()` 接收命令和权限档。默认 `:workspace` 档：工作区内可写，`.git` 与 `.codex` 只读，全盘可读，默认断网；要联网就走 HTTP / SOCKS5 代理，按域名白名单 / 黑名单放行。`codex sandbox` 命令可以脱离 Agent 单独用，也能给 MCP（模型上下文协议）服务器套沙箱。 为什么值得你花时间你在 Gitea 上跑 wayfinder、也在本地跑多个编程 Agent，最怕的是「它读到 key 又联网传出去」；可抄的不是 Codex 的代码，而是这套默认边界：工作区可写 + 敏感目录只读 + 默认断网，以及「单条命令可申请升权、由 harness（执行框架）决定」的审批点。今天花 15 分钟读完默认档，再照抄三件套到你自己的 Agent 配置里。边界：它防的是命令越权，不防「往 node_modules 注入恶意代码、编辑器保存时在沙箱外执行」；Seatbelt 已被 Apple 标为 deprecated（已废弃但仍在用）；Windows 正在迁 MXC。 上手成本15 分钟（读设计；动手要 Codex CLI） 入口https://openai.com/index/inside-the-codex-sandbox 读详情（翻译 + 要点）→
