02 千问办公 2.0：把 Agent 拉进工作群，多人多 Agent 共创 把 Agent 拉进工作群，和团队一起干活。 中文 15 分钟 cn:qbitai ›
是什么阿里 11-09 发布千问办公 2.0，上线三个月来最大升级，全部功能已在客户端全量上线：核心「协作」把团队和数字员工放进同一个协作空间，可实时关联多个钉钉群、文档、AI 表格、AI 听记，支持多会话并行与任务指派；「自动任务」按事件触发（指定人的消息、群里 @我、审批任务），条件满足就自己去读表、填表、发起申请；「人机共创」让多人、多 Agent 在文档 / 表格 / 幻灯片 / 宜搭应用里同时改，可以框选多处意见一次性提交；再加「资料空间」和手机 / 电脑 / 网页三端同步，任务在云端跑、关机也继续。官方给的案例是银泰百货：5 名运营原来要在 60 多个门店群逐个收卡券信息，现在把群和一张 AI 表格接进同一空间，Agent 跨群汇总并自动更新表格。 为什么值得你花时间你做画布 / 工作流，难点从来不是单个 Agent 出图，而是「多人 + 多 Agent 同时改同一个产物」：千问办公把协作单元从「对话」挪到「空间」，把触发从「人喊」挪到「事件」，把修改从「整段重生成」挪到「框选局部意见、一次提交」——这三条都能直接映射到画布的多用户 + 多 Agent 协同，也是你现在 review 冲突最费神的地方。**今天就能做**：装客户端，建一个协作空间，接 2 个群 + 1 张表，配一条「有人 @我缺货 → 读库存 → 填调货表」的自动任务，重点看它怎么处理权限、并发冲突和产物版本。边界：厂商供稿，银泰案例没有第三方数据；强绑钉钉 / 飞书 / 企微生态；企业数据进第三方 Agent，权限与合规要自己评估。 上手成本15 分钟（客户端全量上线，免费） 入口https://qwenwork.cn/download 读详情（翻译 + 要点）→
03 Flide：同一段上下文批量作答，决策推理快 9.5 倍 让决策模型对同一段上下文批量作答。 小而美 15 分钟 hn:show ›
是什么OmniJev 开源的决策模型推理引擎（自托管、pip 安装，Linux + NVIDIA GPU）：把共享上下文只算一次，用一个 mask 让每个问题互相看不见、位置索引仍按「紧接上下文之后」算，一批问题一次前向就出结果；官方在 Qwen3.5-0.8B / QuALITY（5.8k token 上下文、平均 18 个问题）上比 vLLM / SGLang 快 9.5 倍，单问题场景也有 1.5–3 倍，并声称结果与逐个提问逐位一致（只差浮点舍入）。因为 Qwen3.5 的 Gated DeltaNet 只能按 block 边界缓存，vLLM 吃不满，他们自己写了引擎，并把整个前向录成 CUDA graph；支持 30+ 本地模型，6GB NVIDIA 显卡就能跑 0.8B。 为什么值得你花时间你的图像 / 视频管线里有一堆「同一素材、多个判断」的活——这张图是否合规、有没有人脸、镜头类型、能不能当首帧——用通用大模型逐条问，大部分成本浪费在重复读同一段上下文。Flide 把「一次装上下文、批量问、结果不降智」做成了推理原语，9.5 倍是特定 workload 的上限，但「共享 state + 问题并行」这个结构今天就能抄进审核 / 打标服务。**今天就能做**：`pip install flide`，拿 20 张真实素材 + 5 个判断问题跑一遍，对比 vLLM 的每问延迟和总成本。边界：9.5 倍是 0.8B / QuALITY 的最佳场景，单问题接近持平；只在 Linux 测过（Windows 要 WSL2）；需要 ≥6GB NVIDIA 显卡；项目很新（HN 118 分），不要直接上生产。 上手成本15 分钟（pip 装 + 0.8B 模型跑通；需 NVIDIA 显卡） 入口https://github.com/OmniJev/Flide 读详情（翻译 + 要点）→
04 Addy Osmani：带 Coding Agent 的人，先要学会管理 带 Coding Agent 的人，其实在做管理。 中文 15 分钟 cn:infoq ›
是什么Anthropic Claude Code 团队工程师 Addy Osmani 11-08 发长文《Your Coding Agents Made You a Manager》（InfoQ 编译，36 氪转载）：核心不是提示词，而是管理。先让 Agent 自己证明工作完成——测试、构建、Linter，UI 任务开浏览器看；验证命令写进 CLAUDE.md，用 `/goal` 每轮检查目标、Stop Hook 挡住没通过类型检查的结束、`/code-review` 让独立子 Agent 审。上下文只给仓库里没有的（为什么做、约束、怎么算成功）；同一个错纠两次就写进 CLAUDE.md 或封成 Skill，但要定期清理。复杂任务先进 Plan Mode，再开第二个会话让另一个 Agent 以资深工程师视角审计划；`/batch` 把大改拆成 5–30 个独立任务、各自一个 Git Worktree 并行；连续纠错两次仍失败就清会话重写提示词。原则是「可以委派任务，不能委派判断」，指标看 PR 周期、返工 / 回滚率，不看合并了多少 PR。 为什么值得你花时间你在 Gitea 上跑 wayfinder，这套东西几乎是照着痛点写的：Agent 说「改好了」但没跑测试 → 把验证前置成机制；PR 600 行、测试全绿却不值得合 → 委派任务不委派判断；并行 5 个 Agent 反而自己成瓶颈 → 他叫「编排税」，4–5 个已接近一个人能有效管理的上限；同一个问题反复纠 → 沉淀进 CLAUDE.md / Skill 并定期删。这些都不需要换工具，今天改一条就见效。**今天就能做**：把「验证命令 + 成功标准」写进仓库的 AGENTS.md，或给一个长任务加 Stop Hook，挡住没通过类型检查的结束。边界：经验来自 Claude Code，搬到 Gitea / wayfinder 要自己翻译；「4–5 个」是个人体感不是基准；中文是编译稿，原文在 X。 上手成本15 分钟（读 + 先改一条：验证命令写进 AGENTS.md） 入口https://www.36kr.com/p/4062361691575424 读详情（翻译 + 要点）→
05 Agent 撑爆 Git 之后：OpenAI 换后端，Anthropic 换掉 Git Agent 写爆 Git 后，大厂怎么改版本控制。 中文 15 分钟 cn:juejin ›
是什么唐悦玮 11-09 的长文，拆 OpenAI《Scaling Git at OpenAI》与 Anthropic《Redesigning source control at Anthropic》两套方案：OpenAI 的 Pando 只换服务端，Git 命令、协议、客户端原样不动——写方向按分支独立协调，读方向复用同一批 packfile，中位推送延迟降到原来的 1/5，每天发近 1 PB，峰值一小时 57 TB、99% 来自本地磁盘缓存；代价是放弃仓库级一致性、改因果一致，跨分支脚本可能读到现实中从未出现过的组合。Anthropic 的 Scion 把三层都换掉：客户端不再持有完整仓库，提交 / rebase / 合并都在服务端，工作副本虚拟化——7 人 5 个月，基础设施占用小 200 倍，CI 检出从分钟级降到秒级，光 CI 就省 25% CPU；代价是取消全局锁的合并队列，主干可能一段时间是坏的，冲突交给 Claude 去修。 为什么值得你花时间你在 Gitea 上跑 wayfinder，agent 沙箱会把「检出」放大成主要负载，这篇给的不是「要不要重写」，而是三个现在就能量的信号（push 中位延迟、单次 checkout 耗时、同一条分支上同时 push 的次数）和三件不用重写就能做的事：agent 沙箱用 `--filter=blob:none --sparse` 稀疏检出、每个 agent 一个 `git worktree`、把合并队列和必需检查配上。**今天就能做**：在 wayfinder 的沙箱里把全量 clone 换成稀疏检出 + 每 agent 一个 worktree，量一次 checkout 时间和磁盘占用。边界：两套系统都不适合普通团队（Pando 至今没有代码和 API，Scion 官方说不是 Git 的通用替代）；「一天 600 PB」是推演不是实测；本文是二手解读，原始博客链接在文末。 上手成本15 分钟（量三个信号 + 加 worktree） 入口https://juejin.cn/post/7706073526897573939 读详情（翻译 + 要点）→
06 把 Agent 的 PR 长文折叠：Simon Willison 的 details/summary 习惯 把 Agent 写的 PR 长文折叠成一句人话。 跟人 15 分钟 people:simonwillison ›
是什么Simon Willison 11-09 的做法：他现在大部分 PR 由 Claude Code / Codex 开，Agent 写的描述准确、全面，但「读起来像 slop」，第一反应就是「我不看这么多」。他的改法是：PR 最上面放一段人写的开头（这个 PR 干什么、值不值得看，常常加一张截图），把 Agent 的完整长文塞进 `<details><summary>Claude Opus 5.5 Medium</summary>…</details>`——GitHub Markdown 原生支持，折叠后只显示标题行和展开箭头。开头不必自己写，可以从 Agent 长文里挑，但要代表「人的判断：什么值得你花时间」；他给了 5 个真实 PR 作为例子。 为什么值得你花时间你 review agent PR 的时间，很大一部分花在读它自己写的作文上；这个改动 30 秒就能做，效果是让 review 的基本单位回到「人能不能一眼看懂」，和上一条 Addy 的「review 单位应该是人能理解的单位」是同一件事的两个落点。**今天就能做**：把这条模板加进 Gitea 的 PR 模板（或 `.github/pull_request_template.md`），下次 agent 开 PR 时要求「开头一段人话 + 长文折叠」。边界：只解决可读性，不解决「该不该合」；Gitea 对 `<details>` 的渲染要自己验一遍。 上手成本15 分钟 入口https://simonwillison.net/2026/Nov/9/details-summary/ 读详情（翻译 + 要点）→
