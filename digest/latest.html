01 DeepSeek Super-agent：让常驻 Agent 自己盯 GitHub 接活 常驻编码 Agent：自己找活、接活并提 PR。 中文 1 小时 cn:qbitai ›
是什么DeepSeek Harness 团队 10-31 放出的研究原型，一个给单个 GitHub 仓库用的主动编码 Agent，以 bundle 形式装进 DSH。它监听 GitHub（可选飞书），有人 @ 或规则允许时开一个工作项，在独立会话和目录里做完，再回原对话回 PR；网页面板列出需要人处理的事。架构是 Router + Worker：Worker 可直接订阅 PR 评论，事件先过程序规则、再过大模型两级过滤；异步 ReAct 已在 DSH 实现但未默认开启，计算 / 状态 / 执行环境分离，另有独立 Watchdog 检测卡死和跑偏。MIT、TypeScript、7.1k 星，明确标注 research prototype。 为什么值得你花时间你在 wayfinder 和 DSH 上做 Agent 编排，最缺的不是再多一个框架，而是一份把「常驻、多会话、主动接活」拆成 Router / Worker 的工程样本；它的 12.4 分钟中位、15.7 分钟 p95 是约 300 条消息、20 个请求、5 次重复的模拟结果，不是生产指标，但至少给了可复现的比较口径。**今天就能做**：读 README + `docs/000-philosophy.md`，把「什么情况下允许它自己行动」写成你自己的规则；再决定要不要照 SETUP.md 在测试仓库跑一遍。边界：research prototype，不是官方产品；需要 GitHub token 和 DSH 环境；文章里部分设计尚未在原型实现。 上手成本1 小时（读 README + 哲学 / 架构文档；按 SETUP.md 装到测试仓库另算） 入口https://github.com/deepseek-ai/dsh-superagent-prototype 读详情（翻译 + 要点）→
02 higgsfield-faceless-video：把主题做成一条带旁白的成片 把主题或文档做成带旁白和字幕的完整视频。 其他 需要申请 key weekly:skills-sitemap-diff ›
是什么Higgsfield 官方 9 个技能里的端到端出片技能：输入主题或文档，选模式（图解讲解、快剪频道、图片故事、儿童歌曲、说话角色、主持人叠加），先补齐时长 / 画幅 / 语言 / 风格 / 音色 / 音乐 / 字幕，再用 `higgsfield preset` / `voices` / `model get` 查实时参数、用 `generate cost` 估价，最后本地用 ffmpeg + `assemble_blocks.sh` 把分块音视频拼成一条成片。仓库 MIT、版本 0.14.0、1.8k 星；这个技能 6.1K 安装。 为什么值得你花时间你做视频生成 / 一句话成片，这条技能真正值得抄的是「花钱前的检查表」：缺参数先问、绝不编造 preset / voice ID、先估价再生成、依赖缺失就停、成片在本地拼而不是把整条流程交给黑盒；它还明确反对把讲解片做成快剪。**今天就能做**：`npx skills add https://github.com/higgsfield-ai/skills --skill higgsfield-faceless-video`，拿一篇手头文档跑一次 60 秒图解讲解，重点看它的 scene plan 和成本预估，而不是看画质。边界：生成走 Higgsfield 付费积分，技能开源不等于模型免费；9 个技能里只评了 faceless-video；中文旁白 / 字幕质量未验证。 上手成本需要申请 key（Higgsfield 账号 + credits；CLI 安装约 15 分钟，出片按积分） 入口https://www.skills.sh/higgsfield-ai/skills/higgsfield-faceless-video 读详情（翻译 + 要点）→
03 reverse-any-video：把参考视频逆向成可编辑工程 把视频逆成可编辑的 HyperFrames 工程。 其他 半天 weekly:skills-sitemap-diff ›
是什么HyperFrames 的新技能：把一个视频文件逆向成可编辑工程，而不是只给摘要。流程先用 `hyperframes measure probe` 取精确画幅 / fps / 时长，再用 `measure cuts` 找每次剪切（含 jump cut 和同镜头推近），逐层重建 HTML 组件、切出子素材、让人物用 HeyGen 重拍，最后 `check` + 云端 / 本地渲染 + `diff` 逐帧对照原片；产出 `REVERSE.md` 记录哪些是重建、哪些是近似。 为什么值得你花时间你做自动分镜 / 一句话成片，最难的往往不是生成，而是「看懂一条参考片子的镜头、层级和节奏」；这条技能把逆向拆成可检查的工序，还给了逐帧 diff 的验收口径，可以直接借到你的分镜 / 镜头模型里。**今天就能做**：拿一条 15 秒参考片，先只跑 `probe` + `cuts`，看它标出的切点是否和你的肉眼一致；再决定要不要为完整重建付 Pro。边界：HyperFrames Pro 付费功能，Free 不能跑；需要 ffmpeg / python；人物重拍会把素材送 HeyGen；只对有权使用的视频用。 上手成本半天（HyperFrames Pro 付费账号 + ffmpeg / python；先跑 probe / cuts 可 15 分钟） 入口https://www.skills.sh/heygen-com/hyperframes/reverse-any-video 读详情（翻译 + 要点）→
04 remove-animations：给界面动画做一次减法评审 逐个审判界面动画，删掉站不住脚的那些。 其他 15 分钟 weekly:skills-sitemap-diff ›
是什么Emil Kowalski 的减法技能，只做一件事——把界面里现有动画逐个过审，删掉或减弱站不住脚的那些，再清掉孤立的 keyframes / AnimatePresence / import。它给了一棵判定树：键盘触发、每天见 100+ 次、功能性数据上的动画直接删；能说清目的且低频的保留；高频的减到近乎无感；超过 300ms 的压缩。仓库 52.7k 星，这个技能 9.3K 安装。 为什么值得你花时间你的画布 / 工作流界面是高频操作面，Agent 又天然爱加 fade-in、hover-scale、路由过渡；这类动画单个看都合理，叠起来就是「慢」。这条技能的价值是反过来举证：动画要自己证明为什么留下，而且明确要求列出「保留的 2–5 个及理由」，避免一刀切删光。**今天就能做**：对画布页面跑一次 recon + sweep，先只处理键盘命令面板、标签切换和列表 hover 三类，15 分钟能看到手感差异。边界：它不改缓动 / origin / 可中断性，也不判断真机手感；删之前要查 hidden start state、`onAnimationEnd`、AnimatePresence 卸载延迟这些坑。 上手成本15 分钟（装技能 + 对一个页面跑一轮 sweep / gate） 入口https://www.skills.sh/emilkowalski/skills/remove-animations 读详情（翻译 + 要点）→
05 OmniDiff：按内容而不是按行看 diff 按内容而不是按行显示代码、图片和 PDF 的差异。 小而美 15 分钟 hn:show ›
是什么Rust 写的内容感知 diff 工具：25 种语言用 tree-sitter 做结构化 diff，图片 / 字体 / PDF / 压缩包按内容逐像素 / 逐字形 / 逐页比较；既能当 `git difftool`，也能接 jj，支持 TUI、headless、JSON 输出，Windows 有预编译。官方在 2,302 个 fixture 上测得 p50 4.2ms / p90 35.1ms / p99 177ms；442,530 对代码文件里 99.95% 成功。 为什么值得你花时间你每天要读 AI 生成的 patch 和资产变更；普通 diff 把整行标红，真正改的 `sum(numbers)` 和 `len(numbers)` 要自己找，字体 / PDF / 图片干脆只给一句 `Binary files differ`。OmniDiff 把变更收敛到「人眼会注意到的部分」，还能直接看字体字形和 PDF 页面的前后对比，审 UI / 素材改动时省的是注意力。**今天就能做**：下载 Windows 预编译，`omnidiff git configure` 配成 difftool，拿一个最近的 PR 对比 `git diff` 和 `omnidiff` 的可读性。边界：AGPL-3.0，商用闭源要买商业许可；准确率还没达到作者自定的 90% / 99% 目标；VS Code 内建 diff 还不能被替换。 上手成本15 分钟（Windows 预编译 + `omnidiff git configure`） 入口https://github.com/ivankovic/omnidiff 读详情（翻译 + 要点）→
06 Agent 测评全景：绿灯不等于任务完成 用四层证据判断 Agent 是真完成还是假绿灯。 中文 1 小时 cn:juejin ›
是什么掘金作者 hpoenixf 的 ETF Agent 评测复盘，核心是一句话：绿灯只证明某个检查在给定条件下通过，不证明用户任务完成。文章把评测拆成运行 / 证据 / 回答 / 交付四个坐标，给了三套分母的真实数字（计划 120 次、结束 59 次、42 completed / 17 failed；48 次有保存正文，其中 6 次来自 failed；40 inconclusive / 19 failed），还记录了 41 次运行里观测器报告遗漏 851,339 个事件、17 条模型轮次输出缺失。 为什么值得你花时间你在 wayfinder 上做 Agent，最容易自欺的就是「测试全绿 / 状态 completed」；这篇文章给的是可抄的证据链：保留全部计划任务的分母，区分 failed 与 inconclusive，先确认裁判评的是模型候选、服务端实际发送还是客户端展示，再用人工标签校准裁判。**今天就能做**：挑一个你最近修过的 Agent bug，按文中的五字段（任务身份、可重建输入、验收对象、检查规则、执行 / 观测状态）写一条最小 case，先把「哪一层算完成」写死。边界：这是 ETF Agent 的私有评测，不是通用 benchmark；Ragas 只接了环境 / SDK，四项指标仍未评估；多 Agent 的 70/75 只是「进入 Main 输入」，不是采用率或质量提升。 上手成本1 小时（读 36 分钟长文 + 写一条最小 case） 入口https://juejin.cn/post/7703289640062173235 读详情（翻译 + 要点）→
