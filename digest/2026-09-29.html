04 Vespper DOCX MCP：让 Agent 改 Word 而不是当 Word 状态机 专给 Agent 编辑 Word 的 MCP，改 HTML 再翻译回 OOXML。 小而美 1 小时 hn:show ›
是什么YC 背景的 Vespper 2026-09-01 发布的 **DOCX 编辑 MCP**，核心是「不让 Agent 碰 Word」。它先把 `.docx` 转成自研的高保真 HTML（`<w:p>` → `<p>`、`<w:tbl>` → `<table>`，用 CSS 表达 OOXML 的样式关联），Agent 只改 HTML；再由一个**专门训练的小模型当 reconciler**——输入 `(html_old, html_new, xml_old)` 三元组、输出该块的 `xml_new`，无推理、无工具调用、无循环，模型选 3–8B 用 LoRA（rank 16、alpha 32、LR 2e-4、AdamW 8-bit）在 ~16k 自监督样本上 SFT；定位旧 XML 由确定性 locator 负责，最后 diff 出修订记录并补回原文件。作者把动机讲得很实在：`document.xml` 里一个 4–5 句的段落能膨胀成数千 token，Agent 的上下文预算全花在 run 拆分和编号引用上——Harvey 复刻文档编辑系统时得到的诊断是同一句：**不该让一个 Agent 同时当法务助理和 Word 状态机**。基准是自建 2046 条任务 / 279 条测试集，对比 Vespper MCP、Anthropic 的 DOCX skill、裸 python-docx、Office CLI、Adeu、SuperDoc，在 GPT-5.6 Sol 与 Terra 两个模型上跑。结论：**比 DOCX skill 便宜 2.7–2.9 倍、快 2.7–3.5 倍，且通过率更高**；长文档上竞品通过率掉到约 74% 时它保持平稳；差距最大的三类是表格（77.8% vs 71.1%）、修订记录管理（57.7% vs 34.6%）和标题（60.7% vs 46.4%）。边界也写明了：**还不支持评论 / 回复评论、贴图与视频、以及不在 `styles.xml` 里定义的 latent styles**。 为什么值得你花时间你的平台迟早要交付「带模板的成品文档」，而**该在哪一层让 Agent 动手**是你现在就得定的架构问题。这条给了一个可以直接抄的答案：Agent 只操作对人类和模型都友好的表示，把「目标格式的机械细节」交给一个专用小模型去翻译——这跟你把视频 / 图像引擎差异收敛到适配层的思路是同一个形状，只不过它连「翻译」都用模型替掉了手写规则引擎。那组逐域通过率表可以拿去当验收清单（表格 / 修订 / 标题是重灾区）；想立刻试的话文档里有 quickstart，接一个 Agent 大概半小时。 上手成本1 小时（读基准与 quickstart，接一个 Agent 跑通一遍编辑） 入口https://docs.vespper.com/quickstart 读详情（翻译 + 要点）→
05 OpenRig：把多 Agent 团队写成 YAML 再一条命令拉起 用 YAML 定义多 Agent 团队的席位与通信边，一条命令拉起。 中文 1 小时 cn:juejin ›
是什么一篇 2026-09-28 的掘金拆解（作者「秦先生在广东」）。OpenRig 把自己定位成**编排层**而不是又一个编码 Agent：它用声明式 YAML（叫 RigSpec）定义 Pods（代理组）、Seats（席位）与 Edges（通信边），底层用 **tmux 会话持久化**运行状态、SQLite 存实例状态，核心命令 `rig up` 一键启动整个团队、`rig send` 把任务发给指定角色（如 `dev-owner`），主控 Agent 负责自动分配、执行并协调审查。**快照**是它真正解决痛点的地方：`rig down --snapshot` 存状态、`rig up <name>` 原样恢复——多 Agent 协作最大的问题不是智能而是状态碎片化（上下文断裂、会话丢失、协调困难）。预置拓扑有三档：`two-seat starter`（双 Agent 入门）、`conveyor`（四席位流水线，模拟 CI/CD）、`product-team`（含 QA / 设计 / 审查角色）。另有 TUI 展示拓扑、健康状态与日志聚合，以及 **MCP 集成让 Agent 自己调 `rig_up` / `rig_send` 管理所在拓扑**；服务型 Rig 可走 Docker（例如由管理 Agent 操作 HashiCorp Vault）。**两个必须先看的约束**：依赖 Node.js 20/22/24 + tmux + SQLite，**原生 Windows 不支持、WSL2 也未充分验证**；`rig setup` 会改写 `.claude.json` 与 `config.toml` 的信任设置并写入 hooks 把事件遥测发给本地守护进程，所以作者明确建议先备份、并用 `rig setup --dry-run` 预览变更。 为什么值得你花时间你现在并跑多个 Agent 的方式是「多开几个终端 + 人肉转发」，这条给的是把它升级成**有状态、可快照、可恢复**的编排层，而且它的拓扑用 YAML 声明、和你在 Gitea 上跑 wayfinder 那种「流程写进配置」的思路同源。今天最该带走的是它的两个约束而不是功能：**它要写你的 Agent 配置文件**（所以你 AGENTS.md 里「不许动技能目录 / 不许顺手改文件」那类边界在这里正好用得上），以及 **Windows 不给原生支持**——这决定了你要不要在 WSL2 里先试，还是先看它的 RigSpec 设计再决定自研。15 分钟读完取舍清单。 上手成本1 小时（读架构；真跑要在 macOS / Linux 或 WSL2 上） 入口https://juejin.cn/post/7690378863445458979 读详情（翻译 + 要点）→
06 把 Agent 的 while 循环拆掉：一次推理就是一个可恢复单位 把 Agent 的 while 循环拆成单步服务，状态全外置到 journal。 中文 15 分钟 cn:juejin ›
是什么一篇 2026-09-28 的掘金落地复盘（作者「GreenTea」），起点是把几千个会话各塞进一个 Docker 容器跑 while 循环的三个现实问题：CPU 平均利用率不到 5%（九成时间在等 LLM / 等工具 / 等人点确认，却为这 5% 付了 100% 的钱）、宿主机抖动时几十个容器一起挂导致会话历史与依赖全丢、以及每个容器都要自带网关与 Consul 服务发现。作者的判断是：这个循环已经是一个分布式系统，只是还穿着单体的衣服。核心设计一句话——**Agent 的最小可恢复单位不是「会话」而是「一次推理」**：`Step(session)` 拿租约（防并发）→ 读 journal 重建 context → 调 LLM → **单事务写 journal + step 记账 + 工具意图 + 唤醒信号** → 释放租约 → **进程退出，什么都不占**；下一步由工具回调或用户新输入通过队列重新触发。数据模型是五张表（session / event journal / step 幂等账本 / tool_call 意图表 / outbox），共同点是**没有任何一张存「当前对话状态」这种聚合字段**——状态是 `rebuild_context(journal)` 算出来的。三个最值钱的工程点：**单飞用条件 UPDATE 抢租约 + fencing token**（并且他专门区分了「有人接管后旧 worker 的写必须拒绝」与「无人接管时迟到提交必须成功」两个语义相反、测试长得几乎一样的用例）；**LLM 幂等靠意图前置**（调之前先写 `status='inflight'` 的 step 行，之后单事务落 journal + `done`，把「崩在 LLM 已返回、结果未落库」这几毫秒的重复花钱变成可观测的 `attempt` 计数）；**恢复叠四层防线**（outbox 发布 / XAUTOCLAIM / reconciler 检测 stall 会话 / 租约 + memoize 保证重复投递无副作用）。最值得读的是第八节「第一版根本没跑起来」：消费端只有 `XAUTOCLAIM` 没有 `XREADGROUP` 导致整条管道饿死（单测还是绿的，因为 mock 比真实端点宽容）、SSE 忘了推流所以 HTTP 200 却永远收不到事件（**不会失败，只会沉默**）、以及 `AcquireLease` 里多加一个 `cancel = 0` 谓词直接废掉整个取消功能。 为什么值得你花时间你正在用 DSH 的并行 subagent 与 wayfinder 跑长流程，「状态该放哪一层、哪一步可以崩溃重来、崩溃重来时不能重复花的那笔钱怎么记账」是你今天就要面对的一组具体决定，而这篇把每个坑都标了价：`while` 是边界不是实现细节、状态外置的最大收益不是能恢复而是**能审计**（journal 同时是审计日志、`/history` 数据源、context 重建原料与 SSE 内容源，一份数据四个用途）、以及**不变量要写进代码结构而不是文档**（「状态迁移必须带来源状态白名单」这种东西只写在 wiki 里，三个月后必然有人绕过去）。5–10 分钟够你把它那五张表和自己现在的会话存储对一遍，找出哪一层还在用聚合字段——那一层就是下一个会烂掉的地方。 上手成本15 分钟（读第五节状态机与第八节三个 P0 即可，全文约 21 分钟） 入口https://juejin.cn/post/7690413193492217856 读详情（翻译 + 要点）→
