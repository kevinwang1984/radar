是什么掘金上的设计实现解析（作者 狼爷，10-05），配套开源项目 `jasperzxy/JavaManus`：**纯 Java 的 ReAct Agent**，基于 **Spring AI 1.1.0 + Spring Boot 3.4**，默认 LLM 走火山引擎 Ark（豆包），**整体不到 30 个 Java 文件**。架构是四层塔：`ManusAgent`（只负责装配工具）→ `ToolCallAgent`（think → act → observe 编排）→ `ReActAgent`（`step() = think() + act()` 骨架）→ `BaseAgent`（纯状态机 + Memory + 步数控制 + 卡死检测 + 事件分发）。四个关键决策写得很清楚：**手动编排工具调用**（关掉 Spring AI 的 `internalToolExecutionEnabled` 自动执行，自己控制时机，才能截断输出 / 触发事件 / 识别 terminate 工具）、**`maxObserve` 截断超长工具输出**（否则读一次几万行的文件就撑爆 context）、**Memory 用滑动窗口**（`maxMessages` 上限，超了丢最早的）、**SSE + 虚拟线程**推送 `thought` / `tool_call` / `tool_result` / `complete` / `error`。文章最值钱的是五个「代码看起来没问题但会挂死」的真实坑：① **`PythonExecute` 的超时机制完全失效**——先 `getInputStream().readAllBytes()` 再 `waitFor(timeout)`，而 `readAllBytes` 要等到进程退出才有 EOF，**死循环时它永远不返回，超时检查根本没机会执行**；修法是 `CompletableFuture` 异步读输出、先 `waitFor` 再拿结果、超时 `destroyForcibly`。② **文件编辑工具没有沙箱限制**——只校验「是不是绝对路径」，Agent 能读写 `/etc/passwd`；修法是 `workspaceRoot` + 路径归一化前缀校验。③ `System.out.println` 把完整 prompt 打到控制台（含用户输入与工具参数）。④ **LLM 调用失败后向 memory 写错误消息继续循环**，下一轮继续失败，**一直烧到 `maxSteps`**；改成直接终止。⑤ **卡死检测误判**——原来统计历史里所有重复的 assistant
